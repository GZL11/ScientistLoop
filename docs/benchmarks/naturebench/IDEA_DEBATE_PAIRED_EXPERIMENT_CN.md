## 一、要回答的问题与实验设计

**gpt-5.5 判官批判 glm-5.3 产出的 idea、由 glm-5.3 自己改写之后，idea 变好了吗？**

本文只记录**这一个对照实验**：批次 `glm53pair-*-20260902`，10 个任务。

对照做在**每个 run 内部**——同一次辩论产出「原版」与「改写版」两条 idea，
各自独立实现、独立评测。任务、时段、集群负载、资源争抢、跨任务经验快照、
队列优先级全部相同，**唯一变量是有没有过判官**。

> 此前另有 4 个处理组批次（`glm53dbt` / `glm53dbt2` / `glm53dbt3` / `glm53dbt4`）
> 与 1 个 run 级对照组（`glm53ctrl`），均因样本量或混淆问题无法给出结论，见附录 A。
> **本文结论只以本对照实验为准。**

## 三、配对设计

每次辩论"内容真被改过"时，向队列推**两条**——

```
origin   （原版，保留原 id，   idea_debate.arm="origin"）
debated  （改写版，新 id，     idea_debate.arm="debated"）
          共享 pair_id，debated 记 origin_idea_id
```

两条**同优先级**（`_attempt_priority` 见 `arm` 即不加成），原版先入队、改写版紧随；
同优先级按 `seq` 严格 FIFO，因此两条被相邻消费。判无意见 / 作者拒绝 / 判官失败只出一条。

### 配置

```
IDEA / IMPLEMENT = glm-5.3        IDEA_JUDGE = gpt-5.5
mode=respond  rounds=1            闸门 min_elapsed=0 + allow_cross_task_only=1
并发 idea=1 implement=4 evaluation=5    IdeaSpark 容量=4
墙钟 6h（偏离 NatureBench 的 4h 硬约束，本批分数不得进排行榜）
提示词 IDEA_PROMPT_VERSION=v3 / IMPLEMENT_PROMPT_VERSION=v3
```

### 分数口径：**只取每条臂的第一次评测**

一条 idea 会产生**多条 attempt**——`MAX_IMPLEMENT_TURNS=3`，同一 idea 被 refine 数轮，
每轮一条 ExpBank 记录、分数通常递增：

```
idea=32671b9d:  0002=-0.0880 → 0008=-0.0792 → 0013=-0.0747
idea=6deb49f1:  0003=-0.6478 → 0014=-0.1218 → 0018=-0.1007
```

**本文只用每条臂的第一次评测，后续 refine 轮次不参与比较。** 理由：

1. **两臂的 refine 轮数本来就不对齐** —— 实测轮数分布 ``{(1, 1): 1, (1, 2): 2, (2, 1): 3, (2, 2): 3, (2, 3): 3, (3, 2): 4, (3, 3): 9}``，
   只有 **13 / 25** 对轮数相同。取"最好"或"最后"都会把
   *"哪条臂多 refine 了一轮"* 这个与判官无关的变量混进 Δ。
2. **refine 是实现阶段追加的工作**，不属于 idea 本身。要问"辩论让 idea 变好了吗"，
   就该比两条 idea 各自的**第一次落地结果**。
3. 首次评测是唯一在两臂间**结构对齐**的比较点。

> 敏感性：另两种口径（每臂取最好 / 取最后）下 Δ 中位分别为 −0.0014 / +0.0000，
> 同样贴零，但都受轮数不对齐污染，本文不采用。

### 实施过程中修掉的 bug

**首发批次全废**：`_run_benchmark_idea_request` 与 `_enqueue_benchmark_idea_result`
都写死 `ideas[:1]`，配对返回的改写版臂被静默丢弃——**丢的是改写版、留下的是原版**，
等于"辩论照跑、产出全扔"。跑了 3 小时才在产物里发现 `arm` 全是 `origin`。
10 个作业全部 kill，run 目录归档为 `*-aborted-emitpair-bug`。

修复：配对模式下不截断，单条入队逻辑抽成 `_schedule_one_benchmark_idea` 循环调用。
补了 5 个**消费端**测试——此前只测了 `_run_idea_debate` 本身返回两条，
没测 orchestrator 会不会真把两条都入队。重发后 30 分钟内即验证配对生效。

## 四、总体结果

Δ = 首次评测(改写版) − 首次评测(原版)

| 取值口径 | n | 改善 | 变差 | 相同 | Δ 中位 | Δ 均值 | σ |
|---|---:|---:|---:|---:|---:|---:|---:|
| 全部配对 | 25 | 12 | 9 | 4 | +0.0000 | **-0.0373** | **0.3904** |
| 剔除 1 个离群点 | 24 | 12 | 8 | 4 | +0.0023 | **+0.0387** | 0.1189 |

**均值的符号完全由一个点决定**：`s43588-024-00732-2` 的
Δ = **−1.8626**（原版 +0.3451 → 改写版 −1.5175）。
剔掉它，均值从 -0.0373 翻到 +0.0387。

该离群点**数据有效、不是事故**——三个实例全线变差，且 `laplace` 的
improvement 尺度无界（`relative_l2_error` 0.0111 → 0.0419，仅 4 倍，
improvement 就从 −0.340 掉到 **−4.045**），单它一个把聚合从 +0.3451 拖到 −1.5175。
这是我们此前量过的"单实例主导聚合"现象（逐实例极差中位 0.248、p90 1.556）。

**结论：改善 12 / 变差 8（剔离群后），中位 +0.0023，均值 +0.0387，σ 0.1189。
效应量在 ±0.04 级别，而 σ 是它的 3 倍——本实验的样本量分辨不出这个量级的信号。**

### 4.1 按原版分数分层 —— 最强的规律

剔除离群点（24 对）：

| 原版分数 | n | 改善 | 变差 | 相同 | Δ 中位 | Δ 均值 |
|---|---:|---:|---:|---:|---:|---:|
| 原版分数 < −0.15（明显落后） | 19 | 11 | 5 | 3 | +0.0080 | **+0.0597** |
| −0.15 ≤ 原版分数 < 0（接近达标） | 1 | 0 | 1 | 0 | -0.0003 | **-0.0003** |
| 原版分数 ≥ 0（**已达标**） | 4 | 1 | 2 | 1 | -0.0020 | **-0.0512** |

含离群点（25 对）：

| 原版分数 | n | 改善 | 变差 | 相同 | Δ 中位 | Δ 均值 |
|---|---:|---:|---:|---:|---:|---:|
| 原版分数 < −0.15（明显落后） | 19 | 11 | 5 | 3 | +0.0080 | **+0.0597** |
| −0.15 ≤ 原版分数 < 0（接近达标） | 1 | 0 | 1 | 0 | -0.0003 | **-0.0003** |
| 原版分数 ≥ 0（**已达标**） | 5 | 1 | 3 | 1 | -0.0040 | **-0.4135** |

**方案明显落后时改它多半有益（11 改善 / 5 变差，均值 +0.0597）；
方案已经达标时改它期望收益为负（1 改善 / 2 变差，均值 −0.0512；含离群点则 −0.4135）。**

这与 search-policy 侧一个**完全独立**的口径同形——「父 = 当时 run best 时 refine
改善率仅 **52.9%**（≈抛硬币）、delta 中位 **+0.00002**；父≠最优时改善率 71.3%、
中位 +0.010」。**两个互不相关的测量给出同一条规律。**

### 4.2 按判官意见类型分层（剔离群，24 对）

| 意见类型 | n | 改善 | 变差 | Δ 中位 | Δ 均值 |
|---|---:|---:|---:|---:|---:|
| 已达标实例回退（`matched_instance_regression`）| 3 | 3 | 0 | +0.1339 | +0.2081 |
| 资源现实性（`resource_realism`）| 5 | 3 | 2 | +0.0080 | +0.0623 |
| 重复失败（`repeated_failure`）| 2 | 2 | 0 | +0.0097 | +0.0097 |
| 最差实例（`worst_instance`）| 6 | 3 | 1 | +0.0023 | +0.0053 |
| 可证伪假设（`falsifiable_assumption`）| 4 | 2 | 2 | +0.0030 | +0.0024 |
| 指标对齐（`metric_alignment`）| 10 | 4 | 4 | +0.0000 | -0.0019 |

**看起来 指标对齐（`metric_alignment`）是唯一非正的，但这是混淆造成的假象。**

指标对齐 恰好比其他类型更多落在**已达标方案**上（起点 ≥ 0 的配对里它占 3 条）。

完整的混淆检查见 6.5。**除原版分数分层外，本表不构成独立结论。**


⚠️ 这些分层每格只有 2–10 条，且 最差实例（`worst_instance`）在"取最好"口径下是
**5 条全部变差**、在本口径下是 3 改善 / 1 变差——**分层结论对口径极度敏感，
不可作为独立结论使用。**

## 五、配对漏斗：55 次改写为什么只剩 25 对

```
① 判官提意见、作者改写      55 次
② 成功推出两条臂            55 对    ← 配对机制 100% 正常
③ 两臂都拿到有效分数        25 对    ← 可用样本
```

丢失的臂去向：

| 去向 | 条数 | 性质 |
|---|---:|---|
| `not_executed`（未进实现） | 17 | 6h 截止时还在队列 |
| **被 search-policy 消费**（`finished` / `leased`） | **16** | fuse/switch 吃掉，融进别人的 lineage |
| `not_executed`（进了实现，未完成评测） | 9 | 截止时还在评测池外 |
| `engineering_failed` | 3 | 报错退出 |
| `implementing` | 3 | 被杀时还在跑 |
| `queued` | 2 | 排队中 |

两个主因各占三分之一：

- **26 条到点作废**：implement 中位 26.6 分钟 × 4 并发，6 小时最多做 55 次，
  而配对把需求翻倍到 110 条，**产能不够**。
- **16 条被 search-policy 吃掉**：resume ImplementAgent 时会从队列租一条 idea 当
  `offered_idea`，agent 选 `fuse`/`switch` 就调 `finish_lease` 消费掉；选 `refine`
  才 `replay_tail` 放回队尾。实测 fuse 47% + switch 7%，**过半会被吃**。
  待修：`_eligible_new_items` 应跳过带 `arm` 的配对臂。

## 六、四个极端案例：批判的"具体程度"决定成败

### 6.1 最大改善 Δ **+0.4779**（`s41467-025-64512-w`，−0.6478 → −0.1698）

判官 `[重要 / 已达标实例回退]`：

> 方案没有明确把"已达标实例不回退"作为独立约束；它只做按实例的验证集门控，
> 但未规定对已有稳定实例进行回退保护或全局回归检查。

作者接受并加了**显式保守回退硬门**（最终配置验证 AUPR ≥ 纯 de novo 基线 − ε=0.002
才启用，否则结构性回退基线），并把三配置逐实例消融提前为早期验证探针。

### 6.2 第二大改善 Δ **+0.2465**（`s42256-024-00916-5`，−0.8175 → −0.5709）

判官 `[重要 / 资源现实性]`：

> 候选规模、oracle 两阶段筛选和 88,215 行输出的体量与 1 GPU / 8 CPU / 2800s 的申报
> 不够匹配，存在在 4 小时墙钟内跑不完的明显压力。

作者核验证据链属实（题面 + 跨任务经验中"内部用满 3240s、K=100 导致官方评测约 3605s
超时；压到 1200s、K=16 后即拿到 0.0297"的因果证据），把吞吐探针从可选项提升为必做。

### 6.3 第二大变差 Δ **−0.2133**（`s42256-022-00556-7`，**+0.1737** → −0.0395）

判官 `[重要 / 指标对齐]`：

> 方案的训练目标写成各实例 accuracy/MSE 和阈值检查，但没有把这些代理量与题面的
> `aggregate_improvement` 明确连接起来。

作者核对后认为"异议成立"（题面确实只定义实例级指标、聚合公式未公开），加了代理-主指标
对齐层。**但原方案已经 +0.1737，改完掉到 −0.0395。**

### 6.4 最大变差 Δ **−1.8626**（`s43588-024-00732-2`，**+0.3451** → −1.5175）

判官 `[重要 / 指标对齐]`：

> 方案优化与验证的核心量是 per-sample relative-L2，但公开主指标是
> `aggregate_improvement`；两者的关系没有被明确证明。

作者**驳回了前提**：

> Partial rebuttal: the cited evidence (problem/task.md, Section 4) **explicitly defines
> the per-instance primary metric as relative_l2_error** ... so per-instance relative-L2
> **is not an arbitrary proxy but the task's own instance-level scoring quantity**...

**作者是对的——判官这条意见的前提不成立。** 但作者接着写：

> **Accepted kernel of the objection**: the aggregation ... is not public, so pure
> per-instance optimization could misallocate effort.

于是加了四处改动，其中「跨实例 no-regression selection guard」最可疑——
一个更保守的 checkpoint 选择规则，在已经 +0.3451 的方案上挑到了更差的点。
三个实例全线变差（`laplace` rel_l2 0.0111 → 0.0419）。

### 6.5 规律与证据

先说结论：**四个极端案例看上去像"意见类型决定成败"，但做完混淆检查后，
站得住的只有"原版起点"这一条。类型效应基本被起点效应解释掉了。**

#### 证据 1：四个极端案例（n=2 vs n=2）

| | 判官意见类型 | 原版起点 | Δ |
|---|---|---:|---:|
| 最大改善 | 已达标实例回退（`matched_instance_regression`）| −0.6478 | **+0.4779** |
| 第二改善 | 资源现实性（`resource_realism`）| −0.8175 | **+0.2465** |
| 第二变差 | 指标对齐（`metric_alignment`）| **+0.1737** | **−0.2133** |
| 最大变差 | 指标对齐（`metric_alignment`）| **+0.3451** | **−1.8626** |

两个改善都是"具体工程缺陷 + 起点很差"，两个变差都是"论证性缺陷 + 起点已达标"。
**两个变量同时变化，单看这四例无法归因给其中任何一个。**

**指标对齐 由 −0.0019 变成 +0.0266，符号翻转。** 它不是天生有害，
只是恰好比其他类型更多地落在已达标方案上。

#### 结论：哪条留下、哪条否掉

| 说法 | 判定 | 依据 |
|---|---|---|
| **"方案已达标时改它期望收益为负"** | **保留** | 起点分层稳健（见 4.1）；且 search-policy 侧一个完全独立的口径（`current_is_run_best` 时 refine 改善率 52.9%、delta 中位 +0.00002）给出同一形状 |
| "工程缺陷类批判有效、论证类批判有害" | **否掉** | 控制起点后 指标对齐（`metric_alignment`）符号翻正；类型效应基本被起点效应解释 |
| "已达标实例回退（`matched_instance_regression`）特别有效" | **存疑** | 控制起点后仍最高（+0.3059），但 **n=2**，且 σ=0.119 比这个效应量还大 |

**唯一站得住的是起点规律。** 至于"改动是加固还是改结构"这个机制解释
（6.1/6.2 加的是探针和兜底，6.3/6.4 改的是选择规则），**是对四个案例的事后叙述，
本实验没有测量"改动类型"这个变量，不构成证据。**

### 6.6 由此产生的提示词修复（v4）

v3 写了"你保留作者权，可以拒绝修改"，但实测**拒绝率为 0**——
本批 55 次改写、`author_kept` **0 次**。一个从未被行使的权利等于不存在。
复盘出三个缺陷：

1. **只给二元选择**（成立就改 / 不成立就原样重交），没有"前提不成立但看着有可取之处"
   这一格。作者于是自创 `Partial rebuttal` + `Accepted kernel` 然后照改（见 6.4）。
2. **"原样重交"有心理成本**：原封不动重交整份 JSON 看着像没干活，
   而"加一层 guard"既回应了判官又有交付感。
3. **`severity` 是单向压力**：没告诉作者 `major` 也可以被驳回。

`idea_agent_v4.md` 的改动：二元 → 四种处置；**禁止驳回前提后再加改动**（点名禁止
`premise is corrected` + `accepted kernel` 这个写法）；`current_score >= 0` 时只有
`blocking` 级意见才允许改动；`rationale` 必须以 `DEBATE: modified` /
`declined_premise` / `declined_not_bottleneck` / `partial` 开头。

**v4 尚未跑过批次**，待验：拒绝率是否从 0 上升、原版分数 ≥ 0 那一层的负效应是否消失。

## 八、必须写明的局限

### 8.1 致命局限：Δ 里混着实现方差，无法分离

**配对的两条臂是两次独立实现**，不是"同一份代码加个 guard"。原版与改写版是两个
idea 规格，分别交给不同 ImplementActor 从头写代码。所以

```
Δ = 判官效应 + 实现方差
```

而本实验**没有测量实现方差的基线**。旁证：首次评测口径的 σ = **0.3904**（剔离群后
0.1189），而任何分层的效应量都在 ±0.06 以内——**噪声比信号大一个量级**。

要分离必须测出"同 idea 两次实现"的 Δ 分布。

> **更正（2026-09-09）**：这个基线后来在冲刺期排序的重放实验里顺带测到了——
> 同一条 idea 在原 Run 与重放中各实现一次，9 对配对的**绝对差值中位只有 0.017**
> （剔除指标爆炸的一题后，8 对全在 ±0.21 内、7 对在 ±0.09 内，有一对两次完全相同）。
>
> 所以**"补第三条臂"这个建议方向是错的**：实现随机性比 σ 0.119 小近一个数量级，
> 不是 Δ 的主要来源。混在 Δ 里的大头是 **Idea 生成的多样性**——原版与改写版毕竟是
> 两条不同的方案，而那正是 run 间方差本身，补 A/A 臂测不出新东西。
>
> 详见 `LOOP_ABLATION_STUDIES_CN.md` 第 5.2、5.3 节。
若也是 ±0.1，则本实验的结论是"判官效应小于噪声"；若只有 ±0.01，则本文的分层结论才可采信。
代价是产能再降三分之一。

### 8.2 其他局限

- **样本量**：25 对、10 个任务。分层后每层只有 1–19 对，原版分数 ≥ 0 那一层只有 4–5 对。
- **均值被单点支配**：一个 Δ=−1.86 的点让全样本均值从 +0.039 翻到 −0.037。
- **分层结论对口径敏感**：最差实例 在"取最好"口径下 5 条全变差，
  在本口径下 3 改善 / 1 变差。**除原版分数分层外，其余分层不可作独立结论。**
- **6 小时墙钟**偏离 bench 的 4 小时硬约束，**本批分数不进排行榜**。
  两条臂在同一 run 内享受同样 6h，配对比较本身不受影响。
- **1 个 run 集群 Failed**（`s42256-023-00639-z`，存活 3.68h 被外部硬杀，
  `agent.stderr.log` 0 字节、内存峰值 2.6 GiB 远低于 48 限额）。同期集群失败率约 27%。
  **我们这一侧拿不到 exit code / signal / OOM 计数**——orchestrator 记录不了自己的死亡。
- **判官提示词已原地改过一次**（无清单 → 7 项必答清单），所以早期批次的判官行为
  与本批**不可直接比较**。
- **分析过程中的一次错误**：初版统计按 `idea_id` 存 dict，每臂只留下 glob 顺序里
  最后一个 attempt，等于拿"任意一轮"比"任意一轮"。已改为只取首次评测。

## 九、结论与建议

1. **辩论对 NatureBench 分数没有可测收益。** 25 对配对，剔除单个离群点后
   改善 12 / 变差 8、Δ 中位 +0.0023、均值 +0.0387，而 σ = 0.1189 ——
   **效应量比噪声小一个量级**。**不建议默认开启**，`idea_debate.enabled` 保持 `false`。
2. **"已达标就不再改动"是唯一站得住的落地结论。** 原版分数 ≥ 0 那一层期望收益为负，
   且与 search-policy 侧一个完全独立的口径（`current_is_run_best` 时改善率 52.9%）同形。
   这条规则同时适用于辩论和 search-policy 的 refine。
3. **"只保留工程缺陷类批判"这条假设已被自己的数据否掉。** 四个极端案例看似支持它，
   但控制原版起点后 指标对齐的均值由 −0.0019 翻正为 +0.0266（见 6.5）——
   **类型效应基本被起点效应解释掉了，不要据此做类型过滤。**

4. **过程质量好但不转化为分数**：判官能挖出可核查的真缺陷、降低工程失败率
   （11% vs 15%），但这些缺陷往往不是分数瓶颈。
5. **待修的基础设施问题**（与结论无关，但影响后续实验）：
   - `_eligible_new_items` 应跳过配对臂（16 条臂被 search-policy 吃掉）
   - 加 run 级 kill 证据与心跳（集群硬杀无法归因）
   - Idea Judge / Idea Rank Judge / Validity Verifier 三个提示词**还没有版本机制**
6. **若要继续验证**：直接用 v4 提示词重跑并扩大样本。原先写的"先补第三条臂测实现
   方差基线"已作废——见 8.1 节的更正，实现方差实测中位 0.017，不是瓶颈。
   否则无论结果如何都分辨不出信号。

**共同的根本缺陷：对照做在 run 级。** 一个 run 只产出一个成绩，10 个任务最多 10 个
配对点，扣掉集群失败（同期约 27%）只剩个位数；而 run 间方差、集群负载、日期、
跨任务经验库增长全都混在里面无法分离。

**本实验把对照下沉到 idea 级**，一个 run 就能产出十几对，上述混淆项全被同 run 结构消掉。

从这些批次得到的、与本实验结论无关但已确认的机制事实（详见
[`LOOP_DESIGN_INVENTORY_CN.md`](LOOP_DESIGN_INVENTORY_CN.md)）：

- `_idea_backlog` 曾把 `actor_continuation` 计入 IdeaSpark 水位，续跑堆积会把新 Idea
  生产整体卡死——实测有 run 在 70 分钟后再未产出任何新 Idea，辩论闸门因此从未开启
- 辩论闸门只在"要生产新 Idea"时检查，时间与证据两条件都满足后仍可能空等 1.0~1.5 小时
- `cli_agents/idea_judge.md` 初版漏了 `${request_json}`，判官全程看不到待评 Idea 与
  ExpBank 路径，连续给出"无实质缺陷"
