## 二、已确认的缺陷

### 2.1 preflight（smoke-test） 过浅 **[已核实]**

`integrations/naturebench/benchmark.py:159-190` 只检查三项：`entrypoint` 存在、路径归属、Python 语法。**不验证依赖能否 import、权重能否加载**。

后果：`s43588-024-00716-2` 有 5/11 个 attempt 全部挂在 ESMFold 依赖上，preflight 每次放行，**45% 预算白烧**；且最后一个 attempt 只是把首个 attempt 原样重跑。

### 2.2 无收敛/早停机制 **[已核实]**

全仓 grep `early_stop|converge|plateau|patience|pareto|multi_objective|non_regress` **零命中**。晋升逻辑（`orchestrator.py:2896-2921`）纯标量比较。

## 四、关键数据

### 4.1 评测成本 —— 占掉一半预算 **[已核实]**

来源：`experiment_run.duration_ms`，1186 次样本

```
p10 0.7min │ p25 2.8min │ p50 9.1min │ p75 22.3min │ p90 40.8min │ p99 60min(上限)
均值 15.0min │ 超时 21/1186

每个 run 平均 13.5 次评测 × 中位 9.1 分钟 = 2.03 小时 = 4h 预算的 51%
```

最慢的题：`s42256-023-00639-z` 中位 60 分钟（顶到上限），4 小时最多跑 4 次。

### 4.2 资源已饱和 —— 并发无法再提 **[已核实]**

```
60.5% 的评测申请 GPU（718/1186）→ 全部抢同一张 A800 80G
单次评测 CPU 中位 8 核 = AGENT_CPU 全部核数；内存中位 32GiB / 容器 64GiB
当前 evaluations=4 实际已超配（4 并发想要 32 核，容器只有 8 核）
```

**结论：4/4/8 跑不起来。算力固定，只能从"同样 4 小时内提高有效探索"入手。**

### 4.3 Refine 的效果随差距断崖 **[已核实]**

按父版距达标线的差距分组（n=592）：

| 差距 | n | refine 后达标率 |
|---|---:|---:|
| ≤0.05 | 231 | **73%** |
| 0.05–0.2 | 103 | 15% |
| 0.2–0.6 | 171 | 5% |
| >0.6 | 87 | 2% |

**分界线在 0.05。** 注意中位提升反而是差距大的组更高（C 组 +0.0545 > A 组 +0.0012）——烂版本随便改都有进步空间，但**填不满差距**。

尺度无关版本（`steps = gap ÷ 本 run 典型步长`）：≤1 步 36.8%、1–3 步 15.9%、>3 步 3.5%。区分度相当（32.2 vs 32.6 个百分点）但**跨题可比**。

### 4.4 算子选择与状态无关 **[已核实]**

298 次 `search_decision`：

| 父版差距 | refine | fuse | switch |
|---|---:|---:|---:|
| ≤0.05 | 48% | 28% | 23% |
| 0.05–0.2 | 45% | 31% | 24% |
| 0.2–0.6 | 41% | 28% | 31% |
| >0.6 | 37% | 39% | 24% |

差距翻十几倍，refine 占比仅从 48% 降到 37%，switch 纹丝不动。三个算子收益无差异（+0.0084 / +0.0079 / +0.0049）——**机制存在但在空转**。

原因 **[推断]**：`search_opportunity`（`policy.py:150-162`）只提供 `current_idea` 和 `offered_idea` 的**文字描述**，不含当前分数、距达标差距、全场最优、最差子指标——**没有决策依据，只能靠文本感觉挑**。

### 4.5 搜索效率 **[已核实]**

```
973 次评测（不含每条线首次）
  未超过当时最佳：709 次（73%）
  明显更差（低 0.1 以上）：203 次（21%）
```

但**不能据此认为搜索在瞎跑**：56% 的 run 最佳出现在后 1/3，最佳之后只浪费 3 次评测。探索是必要的，**问题是每次代价太高**。

### 4.6 逐实例分化 —— 12/88 **[已核实]**

`aggregate_improvement` = 各实例算术平均，最差实例主导全局。

| Case | aggregate | 达标实例 | 最差实例 | 最差值 | 其余均值 |
|---|---:|---:|---|---:|---:|
| `s42256-024-00956-x` | -0.5283 | 2/4 | 3bpa_300k | **-2.118** | **+0.002** |
| `s42256-025-01003-z` | -0.0767 | 2/5 | custom_illumina | -0.488 | +0.026 |
| `s41592-025-02870-5` | -0.0366 | 1/2 | simulated_dla_tree | -0.096 | +0.023 |

另有 **[已核实]** 此消彼长被标量掩盖的实例：`s41592-023-02032-5` attempt 0005 提升了 benchmark 实例，却让 sars_cov2 从 0.244 跌到 0.190。

### 4.7 Surpass 的两条路径 **[已核实]**

- **7/11** 首次尝试即 ≥0.1（起点就强）
- **4/11** 逆袭，且**突破全部发生在第 3 轮（最后一轮）**，`remaining_turns=0`
  - `-0.8904 → -0.4188 → +0.1975`
  - `-0.0748 → **-0.1443**（中间退步） → +0.1753`

refine 收益**重尾**：中位仅 +0.02~0.05，但成功案例是 +0.19 / +0.25 / +1.09 的大跳。

**警示**：常规"连续两轮无提升就回收"的早停规则**会误杀** —— 上面第二个案例中间那轮是退步的。

### 4.8 跃迁的真实成因 **[已核实]**

`idea` 是**血统级字段**，同一血统所有 revision 共享同一段 rationale。跃迁全部发生在 implementation 层。

最大跃迁 `s43588-025-00842-5`（-0.89 → +0.20）三步：
```
rev1: 一次加 3 样东西（目标编码+交叉特征+k-NN）→ -0.8904
rev2: 删掉破坏 BE_RMSE 的 rank 校准和阈值调优   → -0.4188
rev3: 从另一血统最优 0007(agg=0.193) 出发，只加 1 个特征 → +0.1975
```

**两个可复制的动作**：
1. **回退到跨血统的已知最优基线**（不是自己父链的）
2. **单变量增量**（一次只加一个组件）

失败模式：agent 习惯一次叠加多个改动，出问题后要花 2 轮做减法排查——3 轮预算里 2 轮耗在这上面。

**唯一强区分信号 [已核实]**：诊断式（引用具体 attempt 编号 + 实测数值）STRONG 82% vs WEAK 50%（+32 个百分点）。
**无效信号**：声明要超越 SOTA（55% vs 57%）、风险条数（100% vs 100%）、计划长度（WEAK 反而更长）。

**指标假象说明 [已核实]**：`s41592-025-02893-y` 的 g=-200 由 4 个实例平均而来（-507/-251/-41.5/**-1.34**），最后一个已接近 SOTA。误差型指标下界无穷，收益型指标 -1.0 触底，**g 的绝对值不可跨 case 比较**。

### 27 个 Match-only（Surpass 候选池）

距 0.1 的中位差距 **0.0824**，而其 refine 累计提升中位仅 **+0.0212**（差 4 倍）。

**关键否定 [已核实]**：24 道 Match-only 题平均试过 **5.7 条独立血统**，**0/24 曾有任何血统首次尝试突破 0.1**；题内首次分 std 中位 0.0407，远小于所需的 0.0824。

`s41592-024-02316-4` 试了 11 条血统，最好 0.0309 = 最终 0.0309。

**结论：这是题目天花板，不是 agent 保守。** 靠改 prompt 措辞推 Surpass，预期收益低。题间方差 0.5623 vs 题内方差 0.0851，比值 0.15——**难度由题目决定**。

## 七、已排除的错误结论（避免重复排查）

以下说法在分析中出现过，均已被数据否定。记录于此，以免后续重复走弯路。

| 曾经的说法 | 实情 |
|---|---|
| "存在看门狗强杀 wrapper" | 不存在。是人工杀的；根因是 `PROBLEM_SNAPSHOT_LINK=1` 生成的符号链接指向容器挂载区之外 |
| "31/88 出现坍缩" | **仅 3 个**，其余多样性正常 |
| "坍缩皆因数据缺失" | 仅 1 个成立，另两个数据完整（180MB / 19GB） |
| "有重复实验，需方法指纹去重" | **根本没有重复**。此前 ExpBank 曾把同一血统夺冠后的所有 attempt 都记成排行榜最优分，造成"分数相同=重复实验"的假象（记账逻辑已修） |
| "2/2/4 并发吞吐更低" | 我的 attempts/hour 定义有混淆效应（难度不同、失败也计数、无同题对照），**不作数** |
| "起点决定最终档次" | 中位数掩盖了 4 条逆袭血统 |
| "改 prompt 保守措辞可提 Surpass" | 被 §6 的 0/24 证据否定 |
| "放开 turn 上限只对 3 道近失题有用" | 低估了——4/11 的 Surpass 在最后一轮才成 |
| "加时间/提并发" | 4h 是 bench 硬要求；资源已饱和 |

## 九、论文方向（按证据强度）

**主线建议**：评测信号塌缩 → agent 无法定位问题 → 算子选择退化成随机

| 方向 | 核心证据 | 新颖性评估 |
|---|---|---|
| **B. 逐实例信用分配** | 12/88 存在实例分化；标量掩盖此消彼长 | 算法本身（Pareto/多目标）不新，但**"LLM 科研 agent 在多实例基准上的信用分配"基本无人做**，且批评的是 AIDE/MLE-bench 一类工作的通行做法 |
| **A. 诊断驱动的算子选择** | refine 成功率在 0.05 处相变；算子选择与状态无关 | AOS/bandit 是老问题，新在载体——**实证了 LLM agent 的元认知缺陷** |
| **C. 重尾回报下的停止策略** | 收益中位 +0.02 但成功案例 +0.19~+1.09；4/11 在最后一轮跃迁 | 实证性观察，**样本量不足（n=4），需补实验** |

**独立资产**：88 个 run、1087 条 attempt、完整血统树 + 逐实例分数 + 完整 idea 文本。这种规模的 LLM 科研 agent 搜索轨迹数据集公开的几乎没有。

**诚实提醒**：三个方向的核心算法思想都不新，新的是载体与实证发现。若目标顶会，须把实证发现打磨为主贡献，而非包装算法。
