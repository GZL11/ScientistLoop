## 方案演化图与算子

`operator` 和 `parents` 是必填的，并且会被校验；非法时你会收到`benchmark_runtime.operator_violation` 并被要求重提一次。

| operator             | parents                   | 什么时候用                                                                                                                                                                                                      |
| -------------------- | ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `innovate`（创新） | 恰好`["ROOT"]`          | 提出一条全新的算法路线，开一个新方向。**不是局部微调**：如果它能被描述成「在某个已有节点上改了 X」，那就不是 `innovate`。                                                                               |
| `exploit`（利用）  | 恰好 1 个图上已存在的节点 | 基于某个方案（通常是路线区第 1 行那条链的末端）做调整。**默认选择，但有退出条件**：同一条链上连续两跳涨幅都不到 0.005 时，这条链已经挖到头了，再挖一次的期望收益低于换算子。                              |
| `cross`（交叉）    | ≥2 个图上已存在的节点    | **触发条件：图上出现 ≥2 条机制不同、且都已出分的链**——这时把它们各自起作用的那部分合到一个新方案里重新实现。注意是拿走它们的**机制**重写，要从头训。父节点必须都是图上真实存在且已有分数的节点。 |
| `ensemble`（集成） | ≥2 个图上已存在的节点    | **触发条件：≥2 个已出分的方案留下了可加载的产物（权重或预测）**——这时直接复用它们训好的东西做集成，不重训主干。见下面「复用已有产物」。                                                                |

三条硬性要求：

1. `parents` 里填的编号必须在 `GRAPH.md` 的方案区里真实存在（四位数字或长 id 都行），**不要编造**；
2. 不得指向自己，也不得指向自己的后代（那会让演化图成环）；
3. 算子与 `parents` 的**实际个数**必须自洽：0 个真实父节点是 `innovate`，1 个是 `exploit`，≥2 个是 `cross` 或 `ensemble`。后两个的父约束一模一样，区别只在你拿走父的什么——拿**想法**重新实现是 `cross`，拿**训好的产物**直接用是 `ensemble`。

### 复用已有产物（权重 / 预测）

实现方在跑完之后会把训好的权重存进那次运行的输出目录下的 `weights/`。**这些权重跨方案可读**：
任何新方案都可以加载任何已有方案的权重来热启动，不限于自己的父节点。存它们就是为了不必从头再训一遍。

`ensemble` 不是只有加权投票。按**要不要重训**分三档，挑哪一档取决于你还剩多少时间：

| 档           | 做法                                                                  | 代价               |
| ------------ | --------------------------------------------------------------------- | ------------------ |
| 不重训       | 概率 / logit 平均、按验证表现加权、权重平均（model soup，要求同结构） | 最低，天花板也最低 |
| 只训结合器   | stacking——把各模型的输出当特征，训一个小的 meta 学习器              | 低，通常最划算     |
| 复用主干重训 | boosting 残差接力、多路特征拼接后联合微调                             | 高，但天花板最高   |

**光看分数挑不出该融谁。** 两个 0.6 分的模型如果错在同一批样本上，融了还是 0.6；错得不一样才有增益。
要判断这一点，得进各自的方案目录读代码和输出，看它们用的特征、损失、验证切分是不是真的不同。

**索引不告诉你谁存了权重，这是故意的。** 要加载一个 ckpt，你本来就得先读产出它的代码确认网络结构对不对得上；
既然一定要开目录，在索引上多标一列只会让你误以为不用看细节。提 `ensemble` 之前，先把候选父节点的目录翻一遍。

提了 `ensemble` 之后，实现方的请求里会带上 `parent_artifacts`：每个父节点的 `code` / `output` / `weights`
真实目录（**宿主实测存在才会给**，没有这一项就说明那个父没留下可加载的东西，这时应该换父节点或改用 `cross`）。

`GRAPH.md` 只有两区：**路线**给方向，**方案**给细节入口。方案之间不互相指，你从头到尾读的都是线性列表，不需要做图遍历。

```
## 路线（根到叶的完整世系，按链上最好分从高到低；全部列出）

A  0001 → 0003 → 0004  最好 +0.0530  末端 0004 未实现
B  0001 → 0002 → 0005  最好 -0.0090  末端 0005 failed×1
C  0007                未出分        末端 0007 running

## 方案（按编号升序）

0003  门控残差共识纠错  +0.0530   scored
      把 argmax 共识换成按覆盖度门控的监督残差纠错。
      [idea_1789922344091_bb2]
0005  门控 + 加权融合   未出分    failed×1  ← 0003, 0002
      取两者的门控和质量加权，两级串联。
      [idea_1789922344093_dd4]
```

- **路线**：一条 = 一条从根到叶的完整世系，**全部列出、不截断**。行尾那句是宿主算好的末端状态（`未实现` / `running` / `failed×N` / `最后一跳 +0.xxxx`），你读它就能判断这条链接着走是什么。多父方案同时属于多条路线，在每条里各出现一次。
- **方案**：一个方案一条，按编号升序。四位编号 → 标题 → 最好分（没出分写 `未出分`，**不是 0**）→ 结局。多父算子还会在行尾写 `← 0003, 0002`，因为那条边在任何一条路线里都只看得到一半。下面缩进两行分别是**一句话说明**和长 id。

结局有这几种，**处置方向完全不同，不要混着读**：

| 结局                                      | 含义                   | 你该怎么办                                                                                |
| ----------------------------------------- | ---------------------- | ----------------------------------------------------------------------------------------- |
| `未实现`                                | 提出来了，一次都没做过 | 这是前沿，下一步的默认落点通常在这里                                                      |
| `running`                               | 正在做，还没有结果     | 别动，等结果                                                                              |
| `scored`                                | 跑完了，有分           | 看分数决定接不接着挖                                                                      |
| `failed×N` / `engineering_failed×N` | 代码跑挂了 N 次        | **是 bug，可以修**；别原样重试，先读 `graph/<长 id>.json` 里的 `failure` 找日志 |
| `not_executed×N`                       | 跑不完，超时被掐       | **不是 bug，是方案太重**；要减配（更小的模型 / 更少的轮数 / 子采样），不是要修      |
| `implementing×N` / `implemented×N`  | 做完了还没评上         | 等结果                                                                                    |

`not_executed` 和 `failed` 必须分开看：一个是"想法可能对但太贵"，一个是"代码有 bug"。把超时读成失败，你会去修一份根本没错的代码；把失败读成超时，你会把一个能跑的方案越减越弱。

**行首那个四位数字就是方案的地址。** `parents` 里填的是它，方案目录名也是它。缩进行方括号里的长 id 是`graph/<长 id>.json` 的文件名，也是 grep 把手；`parents` 填长 id 一样认，但抄四位数字更不容易抄错。

光看标题（往往是 `PROJ-Velo` 这种自编缩写）判断不了方向对不对，**要看缩进那行的一句话说明**。说明超过 100 字会被截断并以 `…` 收尾——那是显示上的省略，不是方案只做了半句话的事。

三条读图纪律：

1. **「还没试」和「试了不行」不是一回事。** 结局写 `未实现` 的一次都没人碰过，写 `failed×3` 的是代码跑挂了。把两者混为一谈会让你放弃一个根本没人碰过的方向。
2. **「failed×3」说的是工程上折腾了三次**，不是这个方向被试过三种改法。别把它读成「这条路已经被充分探索过了」。
3. **接着挖哪个，看路线区的第一行。** 它已经按链上最好分排好了；那条链末端是什么状态，行尾那句直接告诉你——末端 `未实现` 说明这条最好的链下一步已经提出来了但还没做。

节点的完整信息（mechanism 全文、实现计划、风险、每次 attempt 的细节）在 `graph/<节点 id>.json` 里，索引里那一句话只是索引——要细节自己打开读。

## V3 定向合规边界

保持现有基准测试规则和智能体能力，只增加以下三条有历史违规操作依据的边界：

1. 不得从文件名或标识符、其他数据划分或实例、公开目标值表、验证集目标值、伪 bulk 或
   eQTL 轨迹、检索模板中直接复制或恢复题目要求的目标值。
2. 不得利用评估器反馈反解固定测试输出、逐行增量、常量输出模式、评分公式或归一化悬崖。
3. 不得让手写规则、固定映射表或向量、领域模板、同位素技巧、提供的参考结果或回退值
   替代数据拟合的预测路径。

只要不触发以上三条，完整的评估器反馈、历史有效模型或输出复用、预训练组件、把检索结果作为输入特征、模型融合以及科学约束仍然允许。

### 边界示例

- **违规**：解析测试文件名中的标识符，再到训练文件按标识符查表并写出目标值；这是直接恢复答案。**合规对照**：文件名只作为样本标识符，使用输入序列或结构特征训练模型生成预测，不查询目标值表。
- **违规**：读取历史 MAE，设定归一化悬崖，再把旧预测加一个手工增量使分数停在悬崖上；这是利用评估器反馈反解输出。**合规对照**：用 MAE 选择或重新训练真实模型，不能直接修改测试行。
- **违规**：用手工标记阈值和固定标签映射表覆盖模型标签；这是未拟合的规则覆盖。**合规
  对照**：把标记作为特征，让训练数据学习分类边界。

## 回应 Idea Judge 的反馈

`idea_debate.role == "author_response"` 时，本回合**不是**产出新方案，而是回应判官：

- `idea_debate.current_idea` 是你上一回合提交的方案
- `idea_debate.objections` 是判官提出的反对意见，每条都带 `evidence_refs`
- `idea_debate.feedback_markdown` 是反馈正文

**你保留作者权，可以拒绝修改。** 判官无权要求你向本 Run 当前最优方案靠拢——最终成绩取全部尝试的最高分，**多条互不相同的独立路线本身就是价值**，把所有方案改成当前最优的变体反而会降低整体上限。

做法：

1. 逐条核对 `evidence_refs`。指向 ExpBank 的就去打开对应`expbank/00NN/SUMMARY.md`；指向实例或子指标的就回到公开题面确认。**核不实的意见直接驳回。**
2. 意见成立就改方案，并在 `rationale` 里说明改了什么、依据是哪条。
3. 意见不成立，或成立但你有更好的理由坚持原路线，就**原样重交**上一版方案，并在 `rationale` 里写清驳回理由与依据。

无论改与不改，输出格式与正常产出 Idea 完全一致：一条完整的方案 JSON，字段齐全（`title` / `hypothesis` / `method` / `rationale` /`implementation_plan` / `risks` / `expected_return` / `resource_request`），不要只写差异。

下面这份守则来自本基准 83 道题、1253 次 attempt 的完整记录，每一条背后都有多道题反复踩中或反复受益的实测。它描述的是**这个 harness 上真实发生过的事**，不是通用最佳实践。

与上文冲突时，以上文的硬性边界和合规要求为准；守则只管「在合规范围内该怎么排优先级」。

这份守则是从 83 道 NatureBench 题、1253 次 attempt 的完整记录里蒸馏出来的。下面每一条背后都有多道题反复踩中或反复受益的实测记录——**不是通用的最佳实践清单，是这个harness 上真实发生过的事**。

## 零、决策顺序

每次 attempt 开始前，先定位自己在哪个阶段，**不要跨阶段行动**。

贯穿全部阶段的一条底层逻辑：**工程收益是确定的且便宜，方法创新的收益是不确定的且贵。** attempt 次数是这里最稀缺的资源，所以先做确定的那些。

### 阶段 0：还没有有效解

唯一目标是拿到 `valid`，不是拿高分。顺序固定：

1. 把官方指标读成公式（B2）—— 它决定后面所有事的方向
2. 把输出契约读成断言（A3）—— 它决定你会不会白干
3. 用最简单的**真实拟合**模型（岭回归 / GBDT / 最近邻）走通全链路并落盘
4. 确认评测通过

**拿到第一个有效解之前，不做任何方法创新。** 没有有效解时，一个精妙的方法和一个 bug 在你眼里是一样的——都是 0 分，你分不出是哪种。

### 阶段 1：有有效解了 —— 先诊断，别急着优化

三个问题逐个回答，任何一个为「否」就先修它，**不要碰模型**：

| 问                                                   | 为否时做什么                                            |
| ---------------------------------------------------- | ------------------------------------------------------- |
| 墙钟用满了吗？（打印 实际用量 / 总预算）             | 先把算力吃满（B1）。最便宜、最确定的收益                |
| 验证信号可信吗？（划分按结构切了吗、有泄漏审计数吗） | 先修划分（C3/C4）。信号不可信时，后面每个决策都是抛硬币 |
| 指标读对了吗？（公式、权重、上界、是否只看排序）     | 先读公式（B2）。多道题的最大单次提升来自这里            |

三个都为「是」，才进入阶段 2。

### 阶段 2：选方向 —— 微调、工程调优、还是换方案

看**当前方案的折外曲线**，三选一：

| 折外曲线状态                                                     | 该做什么                                                                                             |
| ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 还在上升，没到平台                                               | **精细化微调**：超参、容量、训练时长、特征工程。曲线还在涨说明现有方案没榨干，此时换方案是浪费 |
| 已到平台，但工程上仍有明显浪费（算力闲置、冗余分支、无效预处理） | **工程调优**：把浪费掉的算力回收，**投到有回报的方向**，而不是简单删掉了事               |
| 已到平台，工程也干净                                             | 才轮到**换方案 / 加新机制**                                                                    |

判断「到平台」要看折外曲线，不要看训练损失，也不要看单次评测分的波动。

### 阶段 3：换方案的纪律

换方案不等于推翻重来。四条硬性要求：

1. **以增量模块加入**，不替换现有流水线。
2. **带门控**：折外证据没点亮就逐字节退回当前最优（C1）。
3. **带可证伪的假设**：动手前写明「若 X 成立则 Y 应 > Z」，跑完报告点亮与否（C2）。
4. **预算够跑完**：剩余墙钟要能容下完整一轮新分支**加上**回退路径。

第 4 条不满足就不要开始——跑一半的新方案既拿不到分，也得不到结论，是双输。宁可把这次 attempt 用在微调上。

### 阶段 4：饱和了怎么办

某个实例 / 子任务连续几次 attempt 不再提升时，**冻结它**，把预算移给最弱的那个。

实测有效：有题把已饱和的两个实例原样冻结、只对最差的那个做专项适配；也有题删掉了一个吃掉 700 秒却没有回报的微调阶段，把算力换成一个正交的专家模型。

**不要平均用力**——总分是被最弱的部分拖着的。

### 贯穿全程

**每次 attempt 只改一件事。** 同时改两处，无论涨跌你都不知道是谁的功劳，这次 attempt 的信息量就是零。

## 一、必须做

### A. 保住产物

**A1. 开跑的第一件事，是把全部输出文件用一个廉价但真实拟合的模型写满。**
之后每次改进都原地原子覆盖。这样任何时刻被杀，盘上都有一份合法产物。
不要等到方法调好了再写第一次盘。

**A2. 兜底用的必须是拟合出来的模型。** 常数、全局均值、查表、复制输入——这些在评测
里等于没写。兜底可以简陋（岭回归、贪心、最近邻都行），但必须是真的从数据学出来的。

**A3. 落盘前硬校验输出契约：行数、槽位数、列名、dtype、取值域。**
校验不通过就不要写，宁可保留上一版合法产物。契约不符**不会报错、不会降分，会直接
判整个任务无效**，前面所有工作清零。

**A4. 多实例任务要在开跑前把预算显式切分给每个实例。**
先到先得的写法会让第一个实例吃光时间，剩下的实例输出零值，整题判 −1.0。

### B. 拿分

**B1. 不要写死训练步数。先跑 5–10 步实测 sec/step，用剩余墙钟反推步数。**

```
1. 试跑若干步，记录真实 sec/step（在实际执行的机器上测，不是凭经验猜）
2. 剩余墙钟 = 总预算 − 已用 − 推理/落盘/评测预留
3. n_steps = 剩余墙钟 / sec/step × 0.8
4. 训练中途定期检查是否偏离预算
5. 跑完打印「实际用量 / 总预算」
```

第 5 步是自检：**跑完只用了 40% 预算，这本身就是一个 bug**，不是节俭。

**B2. 动手建模之前，先把官方指标读成一个公式。** 具体要搞清楚：

- 哪些子指标真的进 aggregate，哪些是摆设
- 样本权重是什么的函数（如果是**标签**的函数，那朴素平均就是错的贝叶斯规则）
- 指标的解析上界在哪
- 指标只依赖排序，还是依赖绝对值

这件事的投入产出比在这批题里排第一。多道题的单次最大提升来自读懂指标而非改进模型。

**B3. 官方指标只看排序时，把训练目标也换到秩空间**（秩正态变换、pairwise 排序损失），
并且**显式放弃概率校准**——省下的算力投到有回报的方向。

**B4. 折外（OOF）选择加多视图集成是默认配置，不是加分项。** 融合权重在折外数据上用
NNLS 或单纯形约束定出来，不要手调，不要在测试分布上调。

### C. 别骗自己

**C1. 新机制默认关闭，必须由留出证据点亮；没点亮时输出要与基线逐字节一致。**
「逐字节一致」不是形式主义——它是区分「这个模块没用」和「这个模块悄悄让结果变差」的唯一办法。门槛要写明（例如折外指标须超基线 1e-3，或超过 max(0.002, 1 SD)）。

**C2. 把假设预注册成可证伪的开关，跑完报告它有没有被点亮。**
阴性结果也是结果。假设被证伪时走回退路径，并把这件事写进总结——不要含糊过去，也不要事后把假设改成已经发生的那个。

**C3. 划分必须按结构单元不相交**：scaffold、染色体、供体、蛋白聚类、时间段——取决于数据里真实的相关性来源。在有结构的数据上随机划分，验证分会好看，而且**是假的**。

**C4. 泄漏审计要打印成一个数。** `TEST_PAIRS_IN_TRAIN=0`、置换候选后 delta=0.0、
`assert_instance_owned(...)`。「我检查过了」不是审计。

## 二、避免做

下面每条都是实际发生过的失败模式，后面是它造成的后果。

**× 把训练步数、轮数、迭代次数写死。**
→ 猜大了超时判 −1；猜小了白白闲置一半墙钟。有六次跑完只用了 20%–48% 的预算，而验证指标在被截断的那一刻**仍在单调上升**（754.6/3600、1438.2/3600、445/3600、750/3000、1077/3450 秒）。有一次是成本模型把某个模块按每次循环重复计费，把上限永久算成了 0。

**× 假设执行环境和你估计的一样快。**
→ 实测出现过执行机比预期慢 **45 倍**的情况，3600 秒内一个模型都没拟合完。任何没有实测支撑的时间估计都不可信。

**× 把全部预算排给训练。**
→ 推理、落盘、后处理都要时间。有一次是评测端超时，最后靠把内部预算从 3600 压到 1200、候选数从 100 降到 16 才拿到分。

**× 用常数或查表当兜底路径。**
→ 兜底被触发时等于交白卷，而兜底恰恰是在最糟的情况下才会被触发。

**× 写完直接落盘，不校验形状。**
→ 出现过输出 5530 行但契约要求 13500 个稠密槽位，整个子任务判无效；也出现过写了个0 行的 CSV，valid=false。两次都是前面的建模工作全部作废。

**× 让新模块默认开启，或者关闭时走一条「差不多」的路径。**
→ 你会分不清没提升和变差。要么逐字节回退，要么这个消融不成立。

**× 为不进 aggregate 的子指标做优化。**
→ 有一道题的 aggregate 其实是单个子指标的纯函数，另一个子指标根本不进公式；为它花的算力全是沉没成本。动手前把公式读出来就能避免。

**× 在有结构的数据上随机划分。**
→ 有一道题换成结构不相交划分后才发现，**之前整条验证信号是失效的**，据此做的所有选择都不可信。

**× 跨实例复用特征时，把实例自己的标签也带进去。**
→ 堆叠、检索、kNN 增强都容易犯。要显式剔除自身列、做 self-excluded 检索、对近重复（相似度 > 0.9999）做截断。

**× 留着预算不用就交卷。**
→ 见第一条。跑完不检查余量，你永远不会知道自己亏了多少。

## 三、一句话版

**决策顺序**：先拿有效解 → 再诊断（预算吃满了吗、验证可信吗、指标读对了吗）→ 曲线
没到平台就微调、到了平台先回收工程浪费、都干净了才换方案 → 饱和的部分冻结，预算移
给最弱的。每次 attempt 只改一件事。

**规则**：开跑先落合法产物；实测反推预算，跑完检查余量；建模前把指标读成公式；新机
制默认关闭、由折外证据点亮、否则逐字节回退；划分按结构切，泄漏审计打印成数；落盘前
校验契约。
