# 宿主留存架构设计

一个 run 跑完之后，留在磁盘上给人和脚本用的那一份。用来回答三类事后问题：
这个分数是真的吗、能不能再跑一遍、钱和时间花在哪了。

Agent 在 run 期间看到的那一份是另一套结构，见 [AGENT_VIEW_CN.md](AGENT_VIEW_CN.md)。
两者不共用 schema，理由在 §1。

## 1. 为什么不能和 agent view 共用

**主键不一样。** Agent view 的主键是方案（`NNNN`），一切围绕"下一步提什么"组织。
宿主留存的主键是**事件**——一次 agent 激活、一次评测。

两者不是一回事：一个方案会横跨十几次激活和好几次评测；一次激活也可能什么方案都没产出。
硬拼成一套 schema，两边都得变形。

**收录判据也不一样：**

| | 判据 |
|---|---|
| Agent view | agent 读到它，会改变下一步提什么方案 |
| 宿主留存 | 事后有人要回答一个具体问题，而这条记录是唯一答案 |

两条判据都不满足的字段，删掉。不为了对称而保留。

## 2. 三个消费者

| 消费者 | 要回答的问题 | 靠什么回答 |
|---|---|---|
| 审计 | 这个分数是真的吗 | 评测器原始产物、judge 裁决、提交时刻的代码快照 |
| 复现 | 换个时间再跑一遍，得到的是同一个东西吗 | 配置快照、输入快照、模型与提示词版本 |
| 度量 | 时间和钱花在哪 | 每次激活的墙钟、token、费用、结局 |

设计只对这三个消费者负责。不在这三类之内的记录，不留。

## 3. 形状

```
run/
  CONFIG.json          run 开始时固化，之后只读
  activations.jsonl    一次 agent 激活一行
  evaluations.jsonl    一次评测一行
  raw/                 原始物料。只按路径引用，从不内联到上面三样里
```

一份配置 + 两条事件流 + 一堆原始物料。上面三样是可以直接扫描聚合的结构化记录，
`raw/` 是它们指向的大块二进制和长文本。

## 4. 配置快照

run 开始时固化一次，之后不再改。

**完整性标准：拿着这一份，能重新派发一个同样的 run。** 模型、提示词版本、每个开关、
资源额度、各级时限、任务与数据快照的标识，全部在内。

一条硬规矩：**记生效值，不记"用了默认"。** 默认值会随代码变，半年后没人知道当时的默认是什么。

## 5. 激活流

一次 agent 激活一行。

**不要把多次激活合并成一条记录。** 一次唤醒就是一次独立的决策窗口，合并之后无法按激活归因——
哪一次超时、哪一次提交了、哪一次的提醒起了作用，全都算不出来。

每行记：激活 id、所属 run、角色、模型、起止时刻、墙钟、结局、是否提交、token、费用、轨迹引用。

两条格式规矩：

- **结局是平的一个字段**，不嵌在 `failure` 之类的容器里。嵌一层，聚合脚本就会漏读，
  漏读的表现是"全是 None"而不是报错。
- **轨迹引用要带起止偏移。** 同一条轨迹文件会被多次 resume 共享，只给文件名的话，
  事后只能靠时间戳去猜哪一段属于这次激活。

## 6. 评测流

一次评测一行：评测 id、方案编号、第几次实现、输入快照、分数、judge 裁决、产物路径、耗时。

**judge 裁决只记 judge 实际说了什么。** 宿主不得代填、不得推断、不得因为"看起来应该是 valid"
就补一个。裁决缺失就是缺失，缺失本身是有用的信息。

分数可疑时标记，不静默丢弃。丢弃会让后面的人以为这次评测没发生过。

## 7. 数的来源要标明

每个数值属于三类之一：

| 来源 | 例子 | 能不能当证据 |
|---|---|---|
| 宿主实测 | 墙钟耗时、退出码、文件大小 | 能 |
| agent 自报 | 预计运行时长、预期收益 | 不能，只能用来和实测对照 |
| 外部返回 | 评测器分数、CLI 报的 token 和费用 | 能，但要记明来源方 |

同一条记录里混放不同来源时，必须分成不同字段，不能合并成一个"耗时"。
**自报的数不能当证据用**——它记录的是 agent 当时的信念，不是事实。

## 8. 只追加

已经写下的记录不改写。

重跑不覆盖原记录：新增一条，标明它重跑的是哪一条、占的是哪个位置。
两条都在，谁都不许挑好的那条当结果。

## 9. 与 agent view 的唯一接口

方案编号 `NNNN`。

宿主留存的评测流引用它；agent view 不引用宿主留存里的任何 id。单向，不回指。
这样两套 schema 各自演进时不会互相牵制。

## 10. 边界

- **不做二次加工。** 留存的是原始记录，派生指标（中位数、配对差值、分组统计）由分析脚本
  按需算，不落盘成"第二份真相"。
- **不去重。** 内容相同的两次提交是两次独立事件，各记各的。
- **不删。** 低分的、失败的、跑了一半的，全留。
