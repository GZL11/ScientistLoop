# 网络流与能源类任务澄清参考

适用场景：微电网能源调度、光储充调度、园区用能优化、通用网络流（最小费用流/最大流/流量分配）等。

核心判断依据：决策变量是每条弧或每个时刻的流量/功率分配值，存在流量守恒约束或功率平衡约束。**泊位、机位、停机坪等资源的时隙分配请归入 scheduling 类。**

读完数据后，将你对以下每条约束的理解整理成确认问题，逐一向用户确认，**不得因"数据已有"而跳过**。

---

## 需要确认的约束

### 优化目标
- 优化目标是最小化总费用（购电 + 运营 + 惩罚）、最大化收益，还是多目标？
- 多目标时的优先级或权重如何？
- 是否有切换惩罚、弃光惩罚等惩罚项纳入目标函数？

### 储能约束（能源场景）
- 储能 SOC 的范围（上限和下限）是多少？计量单位是什么（kWh / %）？
- 计划结束时对终态 SOC 是否有要求（如必须回到初始值或某固定值）？
- 充放电效率是否对称（充电效率 = 放电效率）？充放电功率上限分别是多少？
- 是否允许同一时刻同时充电和放电（通常禁止）？

### 功率平衡（能源场景）
- 功率平衡约束的精度要求是多少（误差容忍 ≤ X kW）？
- 是否允许向电网售电，还是只能从电网单向购电？
- 光伏/风电若有多余，如何处理（允许弃光/弃风，还是有惩罚）？
- 负荷是否可以削减（需求响应），若可以，削减上限和惩罚如何计算？

### 切换惩罚（能源场景）
- 充放电切换次数是否有限制？超出后如何处理（硬约束还是目标函数扣分）？
- 扣分机制的具体公式是什么（封顶比例、超出几次开始扣分）？

### 网络流约束（通用网络流场景）
- 每条弧/管道的容量上限和下限（最小流量）是多少？
- 是否有节点容量约束（流经某节点的总量不超过上限）？
- 是否允许反向流（双向弧），反向流是否有独立容量限制？
- 流量的计量单位是什么（件/kW/m³）？时间粒度是多少？

### 时间分辨率
- 数据的时间粒度是多少（5 分钟、15 分钟、1 小时）？
- 优化的时间步长与数据粒度是否一致？
- 计划周期是多少（1 天、1 周）？

---

## 常见隐含约束

- **切换扣分上限**：日内切换次数超过阈值才开始扣分，且有封顶比例（如最多扣 25%），需确认具体公式
- **功率平衡严格性**：平衡误差通常要求极小（≤ 0.001 kW），需在模型中作为硬约束而非软约束
- **弃光不罚款**：光伏多余通常允许弃光而不计罚款，但需与业主确认
- **终态 SOC 约束**：计划末尾的储能状态常有归零或归初始值要求，否则储能会被"用尽"形成不公平优势
- **流量守恒**：中转节点流入量必须等于流出量，源/汇节点除外，这是网络流的基本约束，通常无需用户确认但建模时不能遗漏
- **分时电价**：购电成本通常按峰谷平分段计费，需确认各时段价格及时段划分
