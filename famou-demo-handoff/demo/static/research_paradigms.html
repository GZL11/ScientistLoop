范式一：机理建模（ODE / PDE）

药动学 · 生态学 · 神经科学 · 化工反应工程
用数学公式描述"事物随时间/空间如何变化"，然后求解这套方程来预测系统行为。

它解决什么问题？

当你知道（或假设）系统的运行机制——比如药物在体内的吸收-分布-代谢速率、细胞内基因表达的调控关系、化学反应的动力学——你可以把这些机制写成微分方程，然后用计算机数值求解，得到"给定初始条件下，系统未来怎么变化"。

核心概念

概念解释类比
ODE
常微分方程		描述一个变量随时间的变化率
dx/dt = f(x,t)		水池进水速度 − 出水速度 = 水位变化速度
PDE
偏微分方程		同时随时间和空间变化
∂u/∂t = D·∂²u/∂x²		热量在铁棒上怎么从左传到右
参数方程里的常数（如反应速率k、扩散系数D）旋钮——调不同值会得到不同行为
初始条件 / 边界条件系统在t=0时的状态，以及边界上的约束起跑线位置 + 跑道围栏
参数估计 / 拟合用实验数据反推方程里的参数值根据实际水位记录，反算进水管流速

典型工作流（6步）

点击每一步查看详情

1建模（写方程）
研究者根据领域知识，把系统的因果关系写成微分方程组。
例：药物动力学二室模型
dC₁/dt = -(k₁₂+kₑ)C₁ + k₂₁C₂
这一步门槛最高——需要领域专家才能写出合理的方程。
↓
2参数赋值
查文献或做预实验获得参数初始估计值。例如反应速率常数k₁₂=0.5/h，清除率kₑ=0.1/h。参数的量纲和量级需要符合物理意义。
↓
3数值求解（仿真）
用求解器（如MATLAB ode45, Python scipy.integrate.solve_ivp）
输入：方程 + 参数 + 初始条件
输出：浓度-时间曲线、相空间轨迹等
计算通常在秒~分钟级完成。
↓
4与实验数据对比
把仿真曲线和真实实验数据画在一起。
如果偏差大 → 回到步骤2调参数，或回到步骤1改模型结构（比如从一室改二室）。
这是一个反复迭代的过程。
↓
5参数拟合（优化）
用最小二乘法/贝叶斯推断自动找最优参数，使模型预测和实验数据的残差最小。
这一步本质就是优化问题——天然适配进化引擎。
↓
6预测 & 灵敏度分析
用拟合好的模型做预测（"如果剂量翻倍会怎样？"）。
灵敏度分析：扫描参数空间，输出"哪个参数对结果影响最大？"——帮助研究者决定下一步实验应该精确测量哪个参数。

范式二：实验条件优化（DOE / 贝叶斯优化）

化学合成 · 材料制备 · 生物培养基 · 工艺开发
我不完全知道机理，但我可以做实验——问题是实验太贵/太慢，怎么用最少的实验次数找到最优条件？

它解决什么问题？

化学合成、材料制备、生物培养基配方……共同特征：

  • 影响结果的参数很多（温度、压力、催化剂种类、浓度、时间……）
  • 参数之间有交互作用（A和B单独都不重要，但A+B一起就爆炸性地好）
  • 每次实验都有成本（试剂、时间、设备占用）
  • 无法从第一性原理推导最优条件

从传统到前沿：三代方法

点击展开每一代的详细说明

▶ 已淘汰 第一代：OFAT（One Factor At A Time）

固定其他变量，只改一个 → 找到最优值 → 固定它，改下一个。

致命缺陷：完全忽略交互作用。假设温度的最优值在催化剂A时是80°C，在催化剂B时是120°C——OFAT永远发现不了这一点，因为它在测温度的时候催化剂是固定的。

▶ 经典方法 第二代：DOE（Design of Experiments 实验设计）

核心思想：在实验前就设计好一个"采样矩阵"，一次性测多个组合，用统计模型（回归）拟合出"参数→结果"的响应面。

1选因素 & 水平
温度(60/80/100°C)、催化剂(A/B/C)、时间(1h/2h/4h)
↓
2选设计类型
全因子设计(3³=27次) / 正交设计(9次) / 中心复合设计(15次)
实验次数在这一步就完全确定了——不能中途调整策略
↓
3按矩阵做实验
预先确定的全部实验，一口气做完——不管中间有没有看到好的苗头
↓
4统计分析
回归拟合 → 响应面图 → 方差分析(ANOVA) → 找最优区域
↓
5验证实验
在预测最优点做几次重复实验确认

优点系统、统计严谨、能发现交互作用

缺点实验次数预先固定；高维空间下实验数指数爆炸

▶ 前沿方法 第三代：贝叶斯优化（BO）— 闭环自适应

核心思想：边做实验边学习——每做完一批实验，AI更新对"参数→结果"关系的认知，然后智能推荐下一批最值得做的实验。

DOE像旅行前把所有景点都定好，一个不漏地走完。贝叶斯优化像到了一个城市，先随便逛几个地方，然后根据体验决定明天去哪——好评多的方向多探索，差评区域果断放弃。

两个核心组件：

🧠
代理模型 (Surrogate)
高斯过程回归(GPR)：基于已有数据，预测"任意条件下结果会怎样" + "我有多不确定"
🎯
采集函数 (Acquisition)
平衡"探索"(去不确定的区域) vs "利用"(去预测最好的区域)，推荐下一组实验

和DOE的根本区别：

DOE是一次性规划，全部做完再分析；BO是每轮实验后更新认知，动态调整策略。这个"预测→实验→更新"的闭环循环，确保实验资源始终被投向最有可能产生高回报的区域，用远少于DOE的实验次数逼近全局最优。

闭环贝叶斯优化工作流（6步迭代）

1定义搜索空间
确定需要优化的反应参数及其范围：
温度 ∈ [50°C, 150°C]（连续）
催化剂 ∈ {Pd, Pt, Ru, Ir}（离散/分类）
溶剂 ∈ {DMF, DMSO, THF, MeOH}（离散/分类）
浓度 ∈ [0.1M, 2.0M]（连续）
注意：化学场景混合了连续变量和离散变量，这对算法是个挑战。
↓
2初始采样（8-12次随机实验）
用拉丁超立方采样(LHC)或简单随机，在搜索空间里撒几个初始点。
也可以用DOE做初始筛选——两代方法并不冲突，可以组合使用。
↓
3训练代理模型 (Surrogate)
用高斯过程回归(GPR)拟合已有数据，输出两个东西：
• 预测均值：对任意条件预测结果
• 预测不确定性：哪些区域数据少、模型不确定
这两个信息共同驱动下一步决策。
↓
4采集函数推荐下一批实验
常用策略：
• EI (Expected Improvement)：选"比当前最优有最大期望改进"的点
• UCB (Upper Confidence Bound)：选"预测均值+不确定性"最高的点
• Batch BO：一次推荐多个实验点（适合并行实验）
这一步决定了"下一轮去哪里做实验"。
↓
5执行实验 & 分析结果
研究者（或自动化机器人/流动化学装置）在实验室执行推荐的实验。
用HPLC、NMR、光谱等分析结果（产率/纯度/活性）。
这一步是"人在回路"——结果由物理世界产生，不是计算出来的。
↓
⟳更新模型，回到Step 3
把新实验数据加入训练集，重新训练代理模型。
模型越来越准 → 采集函数越来越精准 → 实验效率越来越高。
循环直到：预算耗尽 / 找到满意解 / 模型判断"不太可能找到更好的了"。

和ML代理模型的区别

条件优化ML代理模型
目标找到一组最优实验条件训练一个通用预测模型

范式三：合成生物学 — 基因线路设计

合成生物学 · 代谢工程 · 基因治疗
像设计电路一样设计生物系统：从标准元件库中选取零件，按逻辑规则组装，预测组装后的行为。

它解决什么问题？

合成生物学的目标是工程化改造生命——让细菌生产药物、让酵母合成燃料、让植物检测污染物。为此需要在细胞里构建"基因线路"——一组相互调控的基因，像电路一样执行特定逻辑功能。

核心概念

概念解释电路类比
Part（元件）一段有特定功能的DNA序列
启动子、RBS、编码区、终止子		电阻、电容、晶体管
Device（器件）多个Part组合成一个功能单元
如一个受调控的基因表达单元		运算放大器、逻辑门
Circuit（线路）多个Device连接成一个系统完整电路板
Logic GateAND门：A和B都有→输出
OR门：A或B有→输出
NOT门：A有→不输出		与门、或门、非门
Transfer Function输入浓度→输出浓度的定量关系曲线电压-电流特性曲线
UCFUser Constraint File：描述可用的生物元件库及其特性器件数据手册(datasheet)

访谈中的真实需求

"生物学也有与门、非门。你需要有相应的元件库。有元件层之后会有一个逻辑层——我要什么元件输进去，它会去元件库里调。组装完之后它会帮你预测组装之后什么结果。每一层逻辑很简单，但就是要把它叠起来——什么能跟什么连、什么不能连。"

当前瓶颈（也是伐谋的机会）

▶ 元件库不够大/不够准

iGEM Registry有质量参差不齐的问题——缺乏持续的社区curation，很多元件的Transfer Function只在特定条件下测过。

▶ Cello的局限

只支持NOR/NOT逻辑拓扑，设计规模限于几个门（<10个），搜索空间有限。

▶ 设计→实验的gap

Cello设计出来的线路在实验中经常不work——因为模型没考虑代谢负担、宿主效应、随机噪声。

▶ 逆向设计缺失

现有工具是"正向"的（给定逻辑→找实现），不支持"我想让细菌在X条件下产Y浓度的Z蛋白"这种目标驱动的设计。

最新进展：GenCircuit-RL（2025）

MIT最新的GenCircuit-RL用强化学习替代Cello的模拟退火搜索：

• 支持自然语言描述功能需求（不需要写Verilog）

• 分层验证：逻辑正确性 → 热力学可行性 → 动力学仿真

• 可处理更大规模的线路

  • 元件推荐：用户描述功能需求 → agent搜索iGEM Registry + 文献 → 推荐最合适的元件组合
  • 约束满足搜索：本质是组合优化问题——进化引擎天然适配
  • 仿真验证：组装候选线路后 → 用ODE仿真预测行为 → 自动筛选
  • DBTL循环：Design-Build-Test-Learn闭环——和贝叶斯优化类似的迭代

对伐谋产品设计的启示

从三种范式中提炼出的产品设计原则

1. 三种范式对应三种不同的"评估器"

"最难写的是评估器——你最后到底要什么目标？转换成数学上怎么表达？"

—— 丹宇，西安交大访谈中

范式评估器逻辑数学形式
机理建模模型预测 vs 实验数据的残差最小二乘 Σ(y_pred - y_obs)²
条件优化实验测得的产率/纯度/活性标量值（直接来自实验）
基因线路仿真输出是否匹配真值表 + 动态范围逻辑正确性 + 信号分离度

伐谋需要为不同范式提供不同类型的评估器模板——不能一套通用。

2. 三种范式的"初始代码"形态完全不同

范式初始代码长什么样
机理建模ODE方程组 + 参数定义 + 求解器调用
scipy.integrate.solve_ivp(model, t_span, y0, args=(k1, k2))
条件优化搜索空间定义 + 目标函数 + 约束条件
space = {'temp': (50,150), 'catalyst': ['Pd','Pt','Ru']}
基因线路元件库定义 + 组装规则 + 功能需求
module circuit(output out, input A, B); // Verilog

agent的"澄清阶段"需要问不同的问题——不能用同一套prompt。

3. "人在回路"的位置不同

📐
机理建模

总结：按范式分支的产品设计

不是"一个agent服务所有学科"，而是"一个agent识别范式后，走不同的分支"——不同的澄清问题、不同的初始代码模板、不同的评估器、不同的人机交互边界。
