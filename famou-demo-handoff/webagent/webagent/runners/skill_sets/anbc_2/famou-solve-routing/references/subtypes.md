# 路径规划子族识别指南

> 本文件中的具体数字(节点数、车数、容量值、半径...)都是**典型样貌**——
> 说明该子族常见的规模与约束量级,不是固定参数。
> 实际数字以用户提供的问题描述为准。

问题描述通常不会点名子族。从下面 4 个信号反推:

1. 是否有 `demand` 字段 + 车辆载重上限?
2. 是否多车辆 / 多实例?
3. 是否有时间窗(`earliest_arrival` / `latest_arrival`)?
4. 是否有特殊约束(危化品类别、路网禁令、应急站、地理均衡)?

## 五大子族

### A. 纯 TSP(单车巡回,单实例或多独立实例)

**信号:**
- 单辆车(或每实例一辆车)
- 无容量约束(或宽松到不构成瓶颈)
- 目标:最短总路程
- 规模:100–1000+ 节点

**典型样貌:**
- 单实例 100–500 城市,纯距离最小化
- 多独立实例(如 100+ 实例 × 500 城市),每实例独立求解

**主算法:** 多随机起点 NN + 2-opt(n<300 完整;n>300 限邻域 30)+ ILS 扰动

---

### B. 多车 TSP(mTSP)

**信号:**
- 多车共享单仓库(depot)
- **无**载重约束(或非瓶颈)
- 所有车辆共同服务同一批节点,每节点由且仅由一辆车访问
- 可能有工作量均衡要求
- 规模 100–500 节点,2–20 车

**典型样貌:**
- 1 个 depot,3–5 辆车,数百客户节点共同分配给各车;目标总距离最小或最长路线最短;工作量均衡 spread ≤ 一定比例

> **注意区分多实例 TSP**:若数据有 `instance_id` 字段,每个 instance 有自己独立的城市集和坐标系,则属于"多个独立 A 族问题",每实例单独求解,不是 mTSP。

**主算法:** K-Means 分区(K=车数) → 每区 NN+2-opt → 跨区均衡微调

---

### C. CVRP(容量约束 VRP)

**信号:**
- 节点有 `demand` 字段
- 车辆有载重上限(kg / 吨 / 单位)
- 多车 + 单仓库(depot)
- 目标:总距离 / 总时长,常带工作量均衡

**典型样貌:**
- 数百到数千网点、10–20 车、千 kg 载重、城郊混合;
  Haversine 距离;干线速度 70 km/h + 网点间 35 km/h 量级 + 服务时间 60–180s/点;
  工作量均衡 spread ≤ 10–20%

**主算法:** **容量感知 K-Means**(多种子选最均衡)→ 超载修复 → 每区 NN → 2-opt 限邻域 → 均衡微调

---

### D. VRPTW(带时间窗 VRP)

**信号:**
- 节点有 `[earliest, latest]` 时间窗
- 可能有服务时间
- 目标:满足时间窗 + 最小化车辆数 / 总距离

**主算法:** Solomon 插入启发式 + 时间窗可行性内嵌评估 + 2-opt/Or-opt(每次插入后向后传播 arrival 时间校正)

---

### E. 多约束 VRP(危化品 / 路网禁令 / 多类别车辆)

**信号(任一即定型 E):**
- 节点有 `hazmat_class`(货物分类);车辆有 `allowed_classes`(准入类别)
- **路网图**而非完全图:`segments.csv` 给出路段距离 + 风险密度 + 路段禁令
- 应急站覆盖约束(每个站点半径 R 内必须有车经过)
- 风险/费用复合目标(里程费 + 风险罚款 + 保险)

**典型样貌:**
- 数车数十节点;A/B/C 级车型准入;数个应急站(数十 km 半径);路网禁令(school_zone、blacklist_explosive 等);
  载重上限十吨级;时长上限数小时(含 160 km 强制休息 30 min 之类规则);
  风险上限千级;复合费用结构(里程 + 风险 + 保险等)

**主算法:**
1. 节点按 hazmat_class 拆组 → 与 vehicle.allowed_classes 求兼容矩阵
2. 路网用 Dijkstra(按车型对应不同图)求两两最短"风险加权距离"
3. 容量感知 K-Means 或贪心装载,分配兼容车辆
4. 每车 NN + 2-opt(在路网最短路距离矩阵上)
5. 应急站覆盖:事后检查每站半径 R 内是否有客户节点被某车访问;缺失时拉一节点过来覆盖

---

## 快速判断决策树

```
有 hazmat_class / 路网图 / 应急站约束?
  YES → E(多约束 VRP)
  NO ↓

有 demand + 车辆载重上限?
  YES → C(CVRP),有时间窗加 D(VRPTW)
  NO ↓

多辆车?
  YES → B(mTSP)
  NO → A(纯 TSP)

多实例?→ 不论子族,都按"每实例独立求解"处理
```

## 子族 vs 主算法 vs 时间预算速查

| 子族 | 推荐主算法 | 时间预算 |
|------|-----------|---------|
| A 纯 TSP / 多实例 | NN + 2-opt 限邻域(每实例独立)| 每实例 ≤ 30s |
| B mTSP | K-Means + NN + 2-opt + 跨区均衡 | 60–120s |
| C CVRP | 容量 K-Means + NN + 2-opt 限邻域 + 均衡微调 | 240s |
| D VRPTW | Solomon 插入 + 2-opt + Or-opt | 240s |
| E 多约束 VRP | Dijkstra 路网 + 类别匹配贪心 + 2-opt | 200s |

## 规模 vs 算法

| 节点数 | 推荐 | 典型耗时 |
|-------|------|---------|
| < 100 | NN + 完整 2-opt | < 5s |
| 100–500 | NN + 2-opt 限邻域 30 | 10–60s |
| 500–2000 | K-Means 分区 → 每区局部 NN+2-opt | 60–240s |
| > 2000 | 分区 + Or-opt 风格 LKH 启发式 | 240–280s |

## 城郊/城内混合地形

数据极不均匀(城区密集 + 郊区稀疏)时:
- 城区 cluster **天然就快**,不要强行平摊给郊区
- 均衡目标是"除天然差异外的均衡",CV < 10% 通常足够
- 工作量均衡 ≤X% 指最长车 vs 最短车工时差,不是绝对等时

## 多实例处理

```python
for instance_id in instances:
    nodes = data[data['instance_id'] == instance_id]
    tour, dist = solve_tsp(nodes, time_budget=60)
    routes.append({'instance_id': instance_id, 'route': tour, 'total_distance': dist})
```

**坐标互不混淆**:每实例只用自己的坐标计算距离矩阵,不要把所有点扔到同一矩阵。
