# PRD：深度研究报告的文献引用与可追溯

> 版本：v1.0（2026-07-12）　交付对象：算法团队 + 前端
> 一句话：让深度研究产出的**报告正文带 [n] 引用标号，点击跳到对应文献并高亮，文献展示被引用的原文片段**——把"报告 ↔ 证据"打通，做成可追溯。
> 配套物料：① 本 PRD ② 前端 demo（`PRDdraft/demo`，深度研究+引用已实现，供参考实现） ③ scientist 前端改动快照（`docs/前端快照_20260710/`）。

---

## 1. 背景与问题

深度研究的价值不在"检索到一堆文献"，而在**产出一份每个论断都能追溯到证据的报告**。当前 scientist 前端把文献检索做了，但**报告正文和文献是两张皮**：

- 正文是 agent 自由输出的 markdown，纯渲染，**没有引用标号**；
- 右栏文献是按小领域分组的列表，**和正文对不上**——读者看到一句结论，无法一键定位"它引的是哪篇、原文哪句支撑的"。

结果：文献检索沦为摆设，报告的可信度无法被验证。**这正是要补的核心。**

## 2. 当前现状（scientist 前端，改造基线）

> 代码：`famou-scientist/famou_scientist/assets/web/src/app.tsx`（快照 `docs/前端快照_20260710/`）

- **三栏布局**（最左另有一条可收起的会话 rail：`☰ ＋`）：
  - **左栏 `.pane-chat`**：对话区。深度研究的**报告正文**就在这里（`Chat` → `TextBlock` 用 react-markdown 渲染 assistant 文本，如"可复现性评估 / 一句话总结"）+ 底部输入框（模型选择 / 上传 / 检索文献 / 设计实验 / 写论文）。
  - **中栏 `.pane-products`**：`ProductsPane`，「进程」实时轨迹（任务计划卡 + question/load skill/执行命令/检索文献/webfetch/读取文件 等工具卡）⇄「工作区」文件视图 切换。
  - **右栏 `.pane-right`**：`ResearchPanel`，「产物 / 文献·N」Tab。**文献列表**（`LiteratureList`，按检索 query 分组，如"fish schooling…(24)"，数据来自会话里 `arc_search_literature` 工具输出的聚合 `collectLiterature`）。
- **文献卡 `LitCard`** 现有字段：标题、作者、年份、摘要、原文链接、大屏（`PaperFocus` 含 DOI/摘要/内嵌全文）、★收藏、深入解读。
- **缺口**：
  1. **左栏报告正文无引用标号**（截图里"可复现性评估""一句话总结"等纯文字，无 `[n]`），无法从报告一句话跳到**右栏**对应文献；
  2. 文献**无"被本研究引用的片段"**（只有原文摘要，不知道报告里到底引了它哪句）；
  3. 右栏文献分组排列、**无全局序号**，与报告 `[n]` 无法对应。

> 注：已在快照里试加了「引用片段展开」+「正文 [n] 联动」的前端雏形（见预览页），但**依赖算法侧输出契约**才能真正跑通（见 §5）。

## 3. 要实现的效果（目标）

**深度研究报告 = 正文 + 可点引用 + 可追溯文献**，三者联动：

1. **正文带引用标号**：报告正文在引用处出现 `[1] [2]` 上标（墨绿小号）。
2. **点击跳转**：点正文 `[n]` → 右栏自动切到「文献」Tab + 滚动到第 n 篇 + 高亮（脉冲动画）。
3. **文献带全局序号**：文献卡显示序号徽标 `[n]`，与正文标号一一对应（即使在分组视图下）。
4. **引用片段**：文献卡可展开「引用片段」，列出**本研究正文引用了这篇的哪几句原文**（参考 demo 的 fragments）。
5. **不破坏现有三栏**：以上全部在 scientist 现有三栏内实现，不改布局。

交互示意（真实三栏：左报告 → 右文献）：

```
左栏·报告正文：   …GNN 在 DrivAer 上达 R²=0.94[1]，推理提速千倍[1]。
                                                 │ 点击 [1]
                                                 ▼（中栏进程/工作区不变）
右栏·文献Tab：  ┌ [1] Aerodynamic Drag … GNN ★ ┐ ← 自动切文献Tab + 高亮+滚动
               │  L.Chen · 2024   ▸引用片段2   │
               └───────────────────────────────┘
```

## 5. 算法侧需要配合的契约（关键，前端保证不了）⭐

前端能做的：把 `[n]` 渲染成可点标号、跳转高亮、展示片段。**但下面这几条必须算法侧产出，否则前端拿不到数据、`[n]` 对不上文献：**

### C1. 报告正文引用文献时输出 `[n]` 标号

- agent 写深度研究报告正文时，在引用处输出 `[n]`（如 `…达到 R²=0.94[1]`）。
- **n = 该文献在文献列表中的全局序号（1-based）**，与右栏文献顺序一致。

### C2. 文献检索工具输出结构化字段

- `arc_search_literature` 结果需含：`title` / `authors[]` / `year` / `venue` / `doi` / `url`（现状已部分具备）。
- 前端据此建立「序号 ↔ 文献」映射。

### C3. 每篇文献附「被本研究引用的片段」

- 报告里每处 `[n]` 对应的**原文片段**（这篇文献里支撑该论断的那句/那段），结构建议：
  ```json
  { "paper_index": 1, "fragments": ["GNN 在 DrivAer 数据集上达到 R²=0.94", "推理耗时较全阶 CFD 降低约 1000 倍"] }
  ```
- 产出时机二选一（算法定）：① agent 写报告时同步产出 citation→fragment 映射；② 引用核验阶段（scientist 已有 `arc_verify_citation` / `citation-faithfulness` skill）产出。
- **这条是"可追溯"的灵魂**：没有片段，就只能跳到文献标题，无法验证"到底引了哪句"。

### C4.（可选）引用编号的稳定性

- 若一篇文献被多处引用，`[n]` 复用同一序号；文献列表顺序在一次报告内保持稳定，避免 `[n]` 错位。

## 7. 验收标准

1. 深度研究报告正文出现 `[n]` 上标，样式为墨绿小号、hover 有反馈。
2. 点 `[n]` → 右栏切「文献」Tab + 滚动到第 n 篇 + 高亮 1.6s。
3. 文献卡显示序号 `[n]`，与正文一致。
4. 文献卡「引用片段」可展开，显示本研究引用的原文句子。
5. 全程在现有三栏内，不破坏 7 阶段轨迹 / 文件树 / 现有文献功能。
