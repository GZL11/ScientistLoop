# opencode_famou 对话工作流程

面向产品侧说明伐谋多 agent 体系在一次对话中的协作方式。

---

## Agent 角色一览

| Agent | 角色 | 核心能力 | 不能做的事 |
|---|---|---|---|
| **famou-master** | 策划者，直接面对用户 | 读数据、理解需求、澄清、写 PLAN.md、验证结果、向用户解释 | 不能执行代码、不能写文件（除 PLAN.md） |
| **famou-build** | 执行者，master 的"手" | 写代码、运行脚本、生成产物（CSV/HTML/报告） | 不能再委派其他 agent、不看对话历史 |
| **famou-evolution** | 演化编排器（可选） | 诊断分数趋势、管理演化轮次、判断停止条件 | 不写求解代码、不建议算法方向 |
| **famou-evo-builder** | 演化执行者（可选） | 每轮独立改进方案代码 | 同 build，且每轮 step 上限 30 |

## 首次任务流程

```
用户 💬  上传 orders.xlsx + machines.csv
         "帮我排个程，VIP 优先，目标最少延期"

  ┃
  ┃  ① master 读取数据，判断 query
  ┃     - 能力范围外 → 友善拒绝 + 引导（对话结束）
  ┃     - 缺数据文件 → 引导上传（等待用户补充）
  ┃     - 核心需求   → 进入澄清 ↓
  ┃
  ▼
                                    ┌──────────────────────────────┐
master 💬  确认几个关键信息          │  <clarify> JSON              │
           ┌────────────────────┐  │  前端渲染为卡片               │
           │ 排产目标            │  │  单选/多选 + 默认值           │
           │ (●) 最小化延期     │  │  每轮 ≤4 个问题              │
           │ ( ) 最大化利用率   │  └──────────────────────────────┘
           │                    │
           │ 设备日运行上限？    │
           │ (●) 16h  ( ) 24h  │
           │                    │
           │ 换型时间？          │
           │ (●) 30分钟 ( ) 其他│
           └────────────────────┘

  ┃
  ▼

用户 💬  确认（或修改后确认）

  ┃
  ┃  ② master 判断：还有需要澄清的吗？
  ┃     - 有 → 再出一轮 <clarify>（回到上面）
  ┃     - 没有了 → 输出澄清汇总，进入规划 ↓
  ┃
  ▼

master 💬  澄清汇总：
           目标：最小化总延期，VIP 零延期
           约束：设备 ≤16h/天，换型 30min
           默认值：优先级权重 VIP=10, 普通=1

  ┃
  ┃  ③ master 调用 [famou-plan] → 写 PLAN.md
  ┃     （目标函数 / 硬软约束 / 产物清单 / 可视化规格）
  ┃
  ┃  ④ master 用 [task] 派遣 famou-build
  ┃
  ║══════════════════════════════════════════════════════
  ║  famou-build 接管（用户看到思考流）
  ║
  ║  build 只读 PLAN.md，不看对话历史
  ║  → 写代码 → 分阶段测试 → 逐条验证约束
  ║  → 交付：排程明细.csv + 甘特图.html + 说明.md
  ║  → 若有无法消除的约束违反 → 附 <build_report>
  ║
  ║  build 返回 master
  ║══════════════════════════════════════════════════════
  ┃
  ┃  ⑤ master 验证产物齐全（缺失则重新派遣，最多 2 次）
  ┃     若有 <build_report> → 向用户说明违反项
  ┃
  ▼

master 💬  排程已完成：
           • 87 条订单，84 条准时，3 条低优先级延期 <2h
           • VIP 全部准时 ✓
           • 设备 M-03 利用率 94%，建议关注
           📁 [甘特图.html] [排程明细.csv] [说明.md]

           <sag> 推荐追问：
           「换一种方案？」「增加一台设备的效果？」
```

## 深度演化（可选）

```
用户 💬  触发演化（点击"深度演化"或发送 /evolve 25）

  ┃
  ┃  master 将控制权交给 famou-evolution
  ┃
  ▼
  ╔══════════════════════════════════════════════════════
  ║  famou-evolution 接管
  ║
  ║  初始化演化环境（objective.md + evaluator.py）
  ║
  ║  ┌─ 每轮循环 ────────────────────────────────────┐
  ║  │                                                 │
  ║  │  evolution 派发新的 famou-evo-builder            │
  ║  │       ↓                                         │
  ║  │  evo-builder 独立改进方案 → 返回                │
  ║  │       ↓                                         │
  ║  │  系统 plugin 自动评估 + 归档候选解              │
  ║  │       ↓                                         │
  ║  │  evolution 更新诊断（趋势、饱和度）             │
  ║  │       ↓                                         │
  ║  │  输出进度 → 用户看到 ↓                          │
  ║  │                                                 │
  ║  └─ 直到：预算耗尽 / 停滞 / 全方向饱和 ──────────┘
  ║
  ╚══════════════════════════════════════════════════════
  ┃
  ┃  evolution 返回演化结果给 master
  ┃
  ▼

master 💬  演化完成，25 轮中找到 8 个候选解
           最优分数：12479（vs 初始 14831，↓15.9%）

           | 方案       | 分数  | 改进  |
           |-----------|-------|-------|

  ║══════════════════════════════════════════════════════

  ║
```

## 要点

- **master 永远不执行**，所有"干活"通过 `[task]` 派遣 build 完成
- **PLAN.md 是唯一契约**，build 不看对话历史，master 必须把所有信息写进 PLAN.md
- **澄清用 `<clarify>` 标签**输出结构化 JSON，前端渲染为卡片；每轮 ≤4 题，附默认值
- **后续交互不从零开始**，master 优先基于已有产物回答，只在需要时增量修改（PATCH）或全量重跑
- **演化是独立循环**，由 evolution + evo-builder 这对 agent 驱动，系统 plugin 负责自动评估和归档
