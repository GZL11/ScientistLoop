## 1. 业务清单提取(Step 1)

无论用户以什么形式提供问题(单个文档 / 对话描述 / 多个 spec 文件),开始建模前必须把以下条目逐项抄到脚本顶部注释中。**抄两遍**——遗漏一条硬约束的代价远高于建模过度。

### 1.1 业务清单

- **目标函数构成**:采购 + 持仓 + 损耗 + 缺货 + 调拨 + 切换 + 折扣 + ... 等所有项及权重(尤其权重——评分通常对权重敏感)。
- **硬约束**:容量、产能、保质期、提前期、调拨守恒、不可负库存、合同最低、占比上限、次品率、SOC 边界、充放电互斥...
- **替代规则**:方向(高替低?Premium 替 Basic?)、是否 1:1 等量、是否仅缺货时触发。
- **初始条件**:期初库存、初始在途订单、初始 SOC——通常默认 0,但需要从问题描述中确认。

### 1.2 数据清单(按用户实际命名)

任务描述会指明工作目录、`data/` 下有哪些文件、各文件的字段。**不要假设文件名或字段名**,逐个 `pd.read_csv(...)` 后 `print(df.columns)` 校对一遍。

按用途分类(同一类的文件在不同任务里千差万别):

| 数据类型 | 用途 | 典型字段方向 |
|---------|------|------------|
| 节点/仓库主数据 | DC、仓库、设施的容量、属性 | id、capacity、属性标签 |
| SKU/产品主数据 | 保质期、提前期、单位占用、各项成本 | sku_id、shelf_life、lead_time、unit_cost |
| 需求时间序列 | 每节点每 SKU 每期需求 | dc / sku / period / qty |
| 产能/上限参数 | 供应商月产能、单期补货上限等 | sku / period / cap |
| 业务规则表 | 替代关系、调拨网络、合同最低、折扣 | from / to / 数量或费率 |
| 价格/费率表 | 多供应商定价、汇率、ToU 电价 | supplier or hour / 价格分项 |

### 1.3 交付清单

- 每个产物文件的**确切文件名**与**确切字段名**(中英文大小写空格全部逐字保留)。
- 行数(若问题描述中写明 "N DC × M SKU × T 期 = N×M×T 行不含表头",必须精确匹配,**多/少都不行**;零下单、零调拨的组合也要列出)。
- 可视化要求:图表类型、Tab 切换、配色字体——**按用户指定走**,本 skill 不预设规范。

## 2. 编码规范(Step 5)

### 决策变量

- 命名按 `(dc, sku, t)` 索引,便于调试与提取(实际 id 来自数据)。
- 库存 `inv[(dc, sku, t)] >= 0`、缺货 `short[...] >= 0`、损耗 `waste[...] >= 0`,**全部带 `lowBound=0` 显式写出**:`pulp.LpVariable(..., lowBound=0)`。

### 提前期

- `order[t - L]` 作为第 t 期到货,`t <= L` 时为 0(前 L 期不可避免缺货——这是物理特性,要在报告里说明,**不是 bug**)。
- `lead_time` 通常是 SKU 级而非全局,逐 SKU 读出来用,不要共用一个全局 L。

### 保质期

- **精确**:批次变量 `batch[(dc, sku, t_arrival, t)]`,FIFO 出库;变量数会大幅膨胀,谨慎用于规模 > 1000。
- **近似**:约束 `inv[t] <= sum(demand[t..t+shelf-1])`,避免囤超过保质期能消耗的量;再加大损耗惩罚让求解器自然规避囤积。

### 替代变量

- `sub_in[(dc, sku_low, t)]`(低等级补入)和 `sub_out[(dc, sku_high, t)]`(高等级出库)。
- 等量配对约束:`sub_in[(dc, low, t)] == sub_out[(dc, high, t)]`。
- 出库不超过库存:`sub_out[(dc, high, t)] <= inv[(dc, high, t)]`。

### Hub-Spoke 调拨

- 地区仓的"到货"= 同期 `allocate[dc, sku, t]`(同期完成调拨)。
- 中央仓的"到货"= `purchase[sku, t - L]`(若中央仓有提前期)。
- 地区仓必须**禁止采购**:`order[dc, sku, t] == 0  for dc != central_dc`。

### 容量

两种风格,以问题描述为准:

```python
sum_sku inv[dc, sku, t] * usage_per_unit[sku] <= capacity[dc]   # 加权占用(冷藏体积)
sum_sku inv[dc, sku, t]                       <= capacity[dc]   # 件数风格
```

### 多供应商

- 起订量是**双向蕴含**:`active=1 → sum_p buy >= min`,`active=0 → sum_p buy = 0`,两条都要写。
- 早付折扣的双线性 `buy × early_pay` 要线性化(辅助变量 `buy_early` + 4 条约束)。
- 加权次品率"`<= 2%`"是常数线性,不是除法:`sum(defect_rate[s] * buy[s,p,m]) <= 0.02 * total_demand`。

### 储能调度

- 5 分钟粒度时 1 天 = 288 时段;功率 → 电量用 `× (5/60)` 小时(粒度变了 dt 也要变)。
- 充放电互斥:`mode_charge + mode_discharge <= 1` 加 `charge <= max_power * mode_charge`。
- SOC 单位**统一用 kWh** 建模,避免 % 与 kWh 混淆。

### 求解器

```python
pulp.PULP_CBC_CMD(timeLimit=240, gapRel=0.001, msg=1)
```

复杂二元变量多时切 OR-Tools CP-SAT 或 HiGHS;数值病态时缩放系数(把 1e6 数量级的固定费先除以总需求量,目标值返回时还原)。

### 反例(易写错)

- 避免 `Series.prod()` 这类陷阱(应该 `row['xxx']` 取列)。
- 避免 `for t in range(T)` 而 demand 索引从 1 开始的 off-by-one。
- 避免在 PuLP 里写 `if x > 0:`(x 是变量,Python 会取符号失败)——用 `pulp.lpSum` 与显式约束。
