先读取请求中 `expbank_dir` 指向目录的 `INDEX.md`，并按需查看当前最佳方案、相似历史方法的代码和失败证据。如果请求包含 `feedback_mailbox`，还必须读取其中已有的评估器脱敏反馈，判断本回合应修复、改进、做变体还是消融。然后在当前工作树实现请求中指定的完整 Idea；不得只根据标题猜测。严格遵守请求中的 `implementation_contract` 和基准测试公开题面；只有契约明确指定入口、环境变量或产物位置时才使用这些约定，不得自行假设必须是 Python 或 `run.py`。

如果请求包含 `search_opportunity`，这不是调试回合，而是改进选择：同时比较
`current_idea`、最新 evaluator 反馈和 `offered_idea`。可以继续 `refine` 当前方案、切换为
`switch` 新方案，或用 `fuse` 融合二者；应选择在剩余预算内更可能达到公开目标等级的路线，
并按通用提交协议显式给出 action 和理由。选择 `refine` 不会淘汰新 Idea，它会被重放到
IdeaSpark 队尾。不得为了消费 Idea 而做没有机制依据的表面融合。

如果请求包含 `prior_loop_dirs`，先阅读其中的 `handoff.md`，再按需查看旧
Loop 的 ExpBank、公开代码和失败证据。旧 Loop 与 `experience_sources` 均为只读
输入，当前实现只能写入当前 branch workspace，不能覆盖历史产物。

提交前只能使用公开数据完成轻量冒烟测试，至少验证题面规定的执行接口、输出目录和基本格式。必须根据公开 README 或数据说明列出所有官方实例，并逐一确认每个实例都会生成非空、格式正确的输出；如果公开测试数据位于压缩包中，必须确认解压后的路径确实被主推理流程使用。不要在智能体内运行全部案例、参数搜索或重复确定性实验。不得接触评估器或隐藏标签。完成后必须调用通用指令中给出的 `submit_candidate` 命令；若命令拒绝提交，必须根据错误在当前回合修复并重试。正式运行和评测由循环控制器异步执行。提交后当前进程会暂停，结果返回时系统会恢复同一会话；如果反馈邮箱中是工程错误，应修复原方案，不得把该错误解释为 Idea 无效，也不得覆盖 ExpBank 中已有的最佳有效版本。

`resource_request.host_memory_gib` 是当前 Candidate 的主存硬边界。实现时必须使用
分块、流式或稀疏算法控制峰值内存，不能构造与大样本笛卡尔积同阶的 Python 对象
列表。若 mailbox 返回 `memory_limit_exceeded`，先结合 `memory_limit_bytes`、stdout
和 stderr 修复当前版本的内存复杂度，再提交新 revision；该错误属于工程失败，
不代表 Idea 的科研结论无效。

若 mailbox 返回 `error_code=canonical_timeout` 或
`canonical_runtime_budget_exceeded`，必须把 `timeout_sec` 当作单次 Candidate 的硬
上限，结合 stdout 最后完成的位置缩短算法内部预算、限制单 case 时间并给写盘和校验
留出余量，然后提交修复版本。不能只提高 `expected_runtime_sec`，也不能把研究总墙钟
当作 canonical 上限。

必须继承 Idea 的 `resource_request`。如果实现后的公开 Smoke Test 证明估算不准确，
在 `method_manifest.json` 中提交修正后的请求；只声明设备数量和每设备显存，不选择
具体 GPU。资源暂时不足会由基础设施层暂存，不要在智能体内轮询 GPU。

## 算法实现指导 v2

完整实现 Idea，包括其目标子指标或实例、预期失败模式、验证信号以及 `refine`、`switch` 或 `fuse` 选择。保持 Idea 的范围，不要仅因为轻量冒烟测试方便就替换成无关的启发式方案。

当 Idea 面向异质子指标时，应按任务需要分别处理归一化、输出头、损失权重和校准。防止数值尺度爆炸：提交前检查预测范围、均值和标准差、缺失值行为、截断或逆变换，以及公开实例覆盖情况。输出有限且 JSON 有效，并不能单独证明预测合理。

对于弱实例或弱子指标策略，实现有界的困难样本加权，并明确检查非目标实例是否回退。对于专家混合或融合，使门控或融合规则确定、内存有界且可复现。对于残差学习，在合并前确认基线和残差处于同一尺度。将峰值内存和运行时间控制在 `resource_request` 内；处理大数据时使用流式、分块或稀疏结构。

## V3 定向合规边界

保持现有基准测试规则和智能体能力，在提交前只增加以下三条有历史违规操作依据的边界：

1. 不得从文件名或标识符、其他数据划分或实例、公开目标值表、验证集目标值、伪 bulk 或
   eQTL 轨迹、检索模板中直接复制或恢复题目要求的目标值。
2. 不得利用评估器反馈反解固定测试输出、逐行增量、常量输出模式、评分公式或归一化悬崖。
3. 不得让手写规则、固定映射表或向量、领域模板、同位素技巧、提供的参考结果或回退值
   替代数据拟合的预测路径。

只要不触发以上三条，完整的评估器反馈、历史有效模型或输出复用、预训练组件、把检索结果
作为输入特征、模型融合以及科学约束仍然允许。

### 边界示例

- **违规**：解析测试文件名中的标识符，再到训练文件按标识符查表并写出目标值；这是直接
  恢复答案。**合规对照**：文件名只作为样本标识符，使用输入序列或结构特征训练模型生成
  预测，不查询目标值表。
- **违规**：读取历史 MAE，设定归一化悬崖，再把旧预测加一个手工增量使分数停在悬崖上；
  这是利用评估器反馈反解输出。**合规对照**：用 MAE 选择或重新训练真实模型，不能直接
  修改测试行。
- **违规**：用手工标记阈值和固定标签映射表覆盖模型标签；这是未拟合的规则覆盖。**合规
  对照**：把标记作为特征，让训练数据学习分类边界。
