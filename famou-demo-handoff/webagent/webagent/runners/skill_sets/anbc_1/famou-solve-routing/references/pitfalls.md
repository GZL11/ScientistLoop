### ⚠️ 坑 0B：输出文件残缺/不可解析导致零分（高频）

**现象**：算法逻辑正确，但提交文件为空、行数缺失、存在 NaN、编码错误或含多余索引列，评估器无法解析，直接零分。

**根本原因**：将"算法正确性"与"输出可解析性"混为一谈——即使路径规划逻辑无误，只要输出文件存在以下任一问题，评估器同样无法评分：
- 异常被静默吞掉，写入中断但未报错
- 编码不匹配（如 GBK 写入 UTF-8 环境）
- 分隔符不统一（逗号/制表符混用）
- 数值以科学计数法格式输出
- 含 `index=True` 导致泄漏额外索引列
- NaN 残留（节点未赋值或中间步骤未填充）
- 行数与实例数不符（某实例处理失败后跳过）

**正确做法**：将输出生成视为独立的质量门，与算法逻辑分开验证。

```python
# 零分防护检查（提交前必须通过）
import os, pandas as pd

assert os.path.exists(output_path) and os.path.getsize(output_path) > 0, \
    "输出文件为空或不存在"

df_check = pd.read_csv(output_path)  # 必须无报错
assert set(required_columns).issubset(df_check.columns), \
    f"缺少列: {set(required_columns) - set(df_check.columns)}"
assert df_check.isnull().sum().sum() == 0, \
    f"存在 NaN: {df_check.isnull().sum()}"
assert len(df_check) == expected_rows, \
    f"行数不符: 期望 {expected_rows}, 实际 {len(df_check)}"
print("零分防护检查通过")
```

**验证方法**：以上任意一项不通过则禁止提交，优先排查输出生成逻辑而非算法质量；对每个实例的处理用 try-except 包裹并记录异常，异常后不得写入残缺行。

### 坑 1：节点漏访问 / 重复访问

- 验证：`set(visited) == set(must_visit)` 且 `len(visited) == len(set(visited))`

### 坑 2：多车要求"全部投入"被违反

若问题描述硬要求"K 辆车全部投入，每辆至少服务 1 个节点"：
- K-Means K=K 一般保证非空 cluster，但均衡微调中要强制每 cluster ≥ 1 节点
- 否则均衡微调可能腾空某 cluster

### ⚠️ 坑 3：局部搜索提前退出，未达收敛（高频）

**现象**：局部搜索执行了固定轮数后退出，解质量明显未达局部最优；或仅执行单一搜索算子，忽略互补算子的改善空间。

**根本原因**：将"执行了搜索"等同于"搜索已充分收敛"。固定轮数终止条件在初始解质量差时尤其有害——初始解越差，固定轮数能改善的比例越低，收敛所需轮数越多。

**正确做法**：
- 以"整轮扫描无任何改善"作为局部搜索的**唯一合法收敛标准**，禁止以固定轮数作为退出条件
- 主搜索（如 2-opt）收敛后，必须追加至少一种互补算子（如节点重插入、Or-opt），对质量最差的若干路线重点施加更强搜索
- 跨路线的节点交换/重分配应作为独立阶段执行至收敛，而非可选步骤

```python
# 正确的收敛终止模式
improved = True
while improved:
    improved = False
    for i in range(n):
        for j in neighbors[i]:
            if gain(tour, i, j) > 1e-9:
                apply_move(tour, i, j)
                improved = True
# 主搜索收敛后，执行互补算子
or_opt_until_convergence(tour)
# 再次检查是否有新的改善空间
```

**验证方法**：退出前确认：①主搜索已完成整轮无改善；②互补算子已执行且同样整轮无改善；③跨路线重分配已完成至少一轮全量扫描；打印各路线关键指标与理论估算对比，比值异常则回溯排查。

---

### ⚠️ 坑 4：多目标联合优化退化为串行单目标优化（高频）

**现象**：先优化主目标至收敛，再单独调整均衡性，调整时主目标显著回退；或均衡性与地理集中性的修复互相冲突，循环调整无法稳定。

**根本原因**：将联合目标优化拆解为串行单目标优化，各阶段目标冲突且修复代价高昂。均衡性阈值若使用固定常数，面对不同规模实例会产生假阳性警报或假阴性放行。

**正确做法**：
- 跨路线重分配阶段，将所有软目标改善条件以**逻辑与**的方式联合判断——仅当移动后同时改善或不恶化所有相关目标时才接受
- 均衡性阈值应根据问题规模动态设定（如"标准差 < 均值的 X%"），而非使用固定分钟数/距离数
- 地理集中性等结构性目标应在**聚类阶段**就纳入，而非留到路线优化阶段处理

**验证方法**：提交前打印所有路线的关键指标列表（各维度成本、均衡性度量、地理分布特征），程序化确认：主目标值在合理范围内；均衡性指标满足动态阈值；结构性约束无明显违反；所有路线均非空且约束可行。

## 子族 A/B 专属坑（TSP / mTSP）

### 坑 A1：单起点 NN 质量差异巨大（已强化）

单起点 NN 解长度方差很大，会系统性低估解质量约 5–10%。

**强制要求：多起点（≥5–10 个随机起点）取最优**再做局部搜索，不允许只用单起点。

```python
best_tour, best_dist = None, float('inf')
for start in random.sample(range(n), min(10, n)):
    tour = nearest_neighbor(dist_matrix, start)
    d = total_distance(tour, dist_matrix)
    if d < best_dist:
        best_dist, best_tour = d, tour
# 再对 best_tour 执行 2-opt
```

多起点 + 限邻域 2-opt 是 n=500 规模的**标准配置**，单起点 NN + 全邻域 2-opt 会系统性低估解质量。

**验证方法**：记录并打印各起点初始解距离的最优值与均值，差距显著（如 >5%）时说明多起点策略有效；进入局部搜索前的初始解质量应优于朴素单起点方案。

---

### 坑 A2：2-opt 没限邻域，n=500 就超时（已强化）

完整 O(n²) 单轮约 25 万次评估，需要数十轮才收敛。
**预计算每节点最近 30 邻居**，仅检查邻居对（伪 LK 风格），单轮压到 O(nk)。

**n≥200 实例强制要求**：
1. 预计算 k=30 近邻表（一次性开销）
2. 2-opt 运行直到**完全收敛**（一整轮无改善为止），而非固定轮数
3. n=500 规模下，限邻域 2-opt 完全收敛通常需要 20–50 轮，单实例 <1s

```python
# 预计算近邻表
neighbors = {}
for i in range(n):
    dists = [(dist_matrix[i][j], j) for j in range(n) if j != i]
    neighbors[i] = [j for _, j in sorted(dists)[:30]]

# 限邻域 2-opt，运行至收敛
improved = True
while improved:
    improved = False
    for i in range(n):
        for j in neighbors[i]:           # 只检查邻居对
            if two_opt_gain(tour, i, j, dist_matrix) > 1e-9:
                tour = apply_two_opt(tour, i, j)
                improved = True
```

对于 [0,1]² 均匀分布的 500 城市 TSP，归一化坐标下最优解总距离通常在 **5.5–6.5** 之间；若使用原始未归一化坐标，需结合坐标范围换算后验证量级。

每实例的节点编号都可能从 1 开始，但**坐标系不同**。
必须按实例标识切分，每实例独立计算距离矩阵和路线。

### 坑 A4：tour 闭合处理

报告路径时通常要求"末步返回起点"——输出最后一行节点编号与第一行相同。
计算总距离时不要忘 `dist[tour[-1], tour[0]]`（回程段）。

### ⚠️ 坑 A5：距离/路程数量级合理性校验（高频）

**现象**：求解完成后总距离异常偏小（如远低于理论估算），或与同批次其他实例数量级相差 10 倍以上。

**根本原因**：坐标被错误归一化、单位换算错误、索引方式错误（如行列转置）。

**检查方法**：
- 对均匀分布的 n 城市 TSP，理论最优解估算：`L ≈ 0.7124 × sqrt(n × Area)`，其中 Area 为坐标范围面积（如 [0,100]² 则 Area=10000）。
- 每次求解后立即打印单实例总距离，与理论估算对比：

```python
import math
x_range = coords[:, 0].max() - coords[:, 0].min()
y_range = coords[:, 1].max() - coords[:, 1].min()
area = x_range * y_range
theoretical = 0.7124 * math.sqrt(n * area)
print(f"实际总距离: {total_dist:.2f}, 理论估算: {theoretical:.2f}, 比值: {total_dist/theoretical:.2f}")
# 若比值 < 0.5 或 > 3.0，必须排查
```

- 若任何实例总距离数量级与理论预期偏差超过 **10 倍**，**禁止提交**，必须回溯排查坐标读取、距离计算、索引方式。

---

### ⚠️ 坑 A6：解质量异常均匀——过于完美的红旗（高频）

**现象**：多实例批量求解后，各实例总距离标准差极小（如 <0.1% 均值），或所有实例的值几乎相同。

**根本原因**：距离矩阵被归一化到固定范围、结果被截断、或所有实例用了同一套坐标。

**处理**：随机抽取 3–5 对节点，手动计算距离并与代码输出对比，误差 <0.1% 方可继续。

---

### ⚠️ 坑 A7：初始解多样性不足导致局部最优陷阱（新增）

**现象**：多实例批量求解后，部分实例的解质量明显差于其他实例（同规模下差距 >15%），且局部搜索无法改善。

**根本原因**：初始解构建的起点选择偏向某一区域（如固定从编号最小的节点出发），使初始解分布偏向某一局部结构，后续局部搜索的改善空间受限。

**正确做法**：
