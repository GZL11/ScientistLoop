## 方案演化图与算子

如果请求包含 `idea_runtime.idea_graph_dir`，先读该目录下的 `GRAPH.md`。这张图上**每个节点都带最好分和一句话说明**，`expbank/INDEX.md` 的「节点」列可以把 attempt 直接对回节点。

每条 Idea 必须声明它是怎么被造出来的：`operator`（必填）加 `parents`（父节点 id 数组）。这两个字段会被校验，非法时你会收到 `benchmark_runtime.operator_violation` 并被要求重提一次。

| operator | parents | 什么时候用 |
| --- | --- | --- |
| `innovate`（创新） | 恰好 `["ROOT"]` | 提出一条全新的算法路线，开一个新方向。**不是局部微调**：如果它能被描述成「在某个已有节点上改了 X」，那就不是 `innovate`。 |
| `exploit`（利用） | 恰好 1 个图上已存在的节点 | 基于某个节点（通常是「现在爬到哪了」那条链的末端，或「最该接着挖的」第 1 行的父节点）做调整。这是默认选择——只要现有方案的折外曲线还在涨，继续挖它就比换方向划算。 |
| `cross`（交叉） | ≥2 个图上已存在的节点 | 参考多个节点、融合它们各自的优势。父节点必须都是图上真实存在且已有分数的节点。 |

三条硬性要求：

1. `parents` 里的 id 必须在 `GRAPH.md` 里真实存在，**不要编造节点 id**；
2. 不得指向自己，也不得指向自己的后代（那会让演化图成环）；
3. 算子由 `parents` 的**实际个数**决定，两者必须自洽：0 个真实父节点就是 `innovate`，1 个是 `exploit`，≥2 个是 `cross`。

`GRAPH.md` 分四段，各自回答一个不同的决策问题。**每一行都是自足的**：父节点直接写成「标题」(分数)，你不需要回到另一行去查某个 id 是谁、考了多少分（父标题超过 100 字会被截断并以 `…` 收尾——那是显示上的省略，不是方案叫这个名字）。每个节点下面缩进那行是它的**一句话说明**——光看标题（往往是 `PROJ-Velo` 这种缩写）判断不了方向对不对，要看那句话。

- **现在爬到哪了**：最好的一条链和每一跳的涨幅 → 判断「继续挖」这件事到目前为止有没有兑现；
- **最该接着挖的**：提了却一次都没实现的方案，**已经按父节点的最好分从高到低排好**，所以**第 1 行就是默认答案**；
- **试过但还没有分的**：已经实现过但没拿到分的方案，写明是失败了几次（别原样重试）还是还在跑（等结果）；
- **全部方案**：全貌，按最好分降序。

**节点 id 只出现在每行末尾的方括号里**，格式是 `[自己的 id ← 父的 id…]`（前两段的节点自己还没有可引用的产物，所以只写 `[← 父的 id]`）。`parents` 要填 id，就从方括号里取——**正文里的「标题」是给你读的，不是 id**。两个父的标题被截断后可能看起来一样，方括号里的 id 才是唯一的。

两条读图纪律：

1. **「还没试」和「试了不行」不是一回事。** 前者在「最该接着挖的」，后者在「试过但还没有分的」，两段物理分开。把两者混为一谈会让你放弃一个根本没人碰过的方向。
2. **「实现 3 次全部失败」说的是工程上折腾了三次**，不是这个方向被试过三种改法。别把它读成「这条路已经被充分探索过了」。

节点的完整信息（mechanism 全文、实现计划、风险、每次 attempt 的细节）在 `graph/<节点 id>.json` 里，索引里那一句话只是索引——要细节自己打开读。

保持现有基准测试规则和智能体能力，只增加以下三条有历史违规操作依据的边界：

### 边界示例

- **违规**：解析测试文件名中的标识符，再到训练文件按标识符查表并写出目标值；这是直接
  恢复答案。**合规对照**：文件名只作为样本标识符，使用输入序列或结构特征训练模型生成

- **违规**：读取历史 MAE，设定归一化悬崖，再把旧预测加一个手工增量使分数停在悬崖上；

- **违规**：用手工标记阈值和固定标签映射表覆盖模型标签；这是未拟合的规则覆盖。**合规

## 零、决策顺序

每次 attempt 开始前，先定位自己在哪个阶段，**不要跨阶段行动**。

贯穿全部阶段的一条底层逻辑：**工程收益是确定的且便宜，方法创新的收益是不确定的且贵。** attempt 次数是这里最稀缺的资源，所以先做确定的那些。

### 阶段 0：还没有有效解

唯一目标是拿到 `valid`，不是拿高分。顺序固定：

1. 把官方指标读成公式（B2）—— 它决定后面所有事的方向
2. 把输出契约读成断言（A3）—— 它决定你会不会白干
3. 用最简单的**真实拟合**模型（岭回归 / GBDT / 最近邻）走通全链路并落盘
4. 确认评测通过

**拿到第一个有效解之前，不做任何方法创新。** 没有有效解时，一个精妙的方法和一个 bug 在你眼里是一样的——都是 0 分，你分不出是哪种。

### 阶段 1：有有效解了 —— 先诊断，别急着优化

三个问题逐个回答，任何一个为「否」就先修它，**不要碰模型**：

| 问                                                   | 为否时做什么                                            |
| ---------------------------------------------------- | ------------------------------------------------------- |
| 墙钟用满了吗？（打印 实际用量 / 总预算）             | 先把算力吃满（B1）。最便宜、最确定的收益                |
| 验证信号可信吗？（划分按结构切了吗、有泄漏审计数吗） | 先修划分（C3/C4）。信号不可信时，后面每个决策都是抛硬币 |
| 指标读对了吗？（公式、权重、上界、是否只看排序）     | 先读公式（B2）。多道题的最大单次提升来自这里            |

三个都为「是」，才进入阶段 2。

### 阶段 2：选方向 —— 微调、工程调优、还是换方案

看**当前方案的折外曲线**，三选一：

| 折外曲线状态                                                     | 该做什么                                                                                             |
| ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 还在上升，没到平台                                               | **精细化微调**：超参、容量、训练时长、特征工程。曲线还在涨说明现有方案没榨干，此时换方案是浪费 |
| 已到平台，但工程上仍有明显浪费（算力闲置、冗余分支、无效预处理） | **工程调优**：把浪费掉的算力回收，**投到有回报的方向**，而不是简单删掉了事               |
| 已到平台，工程也干净                                             | 才轮到**换方案 / 加新机制**                                                                    |

判断「到平台」要看折外曲线，不要看训练损失，也不要看单次评测分的波动。

### 阶段 3：换方案的纪律

换方案不等于推翻重来。四条硬性要求：

1. **以增量模块加入**，不替换现有流水线。
2. **带门控**：折外证据没点亮就逐字节退回当前最优（C1）。
3. **带可证伪的假设**：动手前写明「若 X 成立则 Y 应 > Z」，跑完报告点亮与否（C2）。
4. **预算够跑完**：剩余墙钟要能容下完整一轮新分支**加上**回退路径。

第 4 条不满足就不要开始——跑一半的新方案既拿不到分，也得不到结论，是双输。宁可把这次 attempt 用在微调上。

### 阶段 4：饱和了怎么办

某个实例 / 子任务连续几次 attempt 不再提升时，**冻结它**，把预算移给最弱的那个。

实测有效：有题把已饱和的两个实例原样冻结、只对最差的那个做专项适配；也有题删掉了一个吃掉 700 秒却没有回报的微调阶段，把算力换成一个正交的专家模型。

**不要平均用力**——总分是被最弱的部分拖着的。

### 贯穿全程

**每次 attempt 只改一件事。** 同时改两处，无论涨跌你都不知道是谁的功劳，这次 attempt 的信息量就是零。

## 一、必须做

### A. 保住产物

**A1. 开跑的第一件事，是把全部输出文件用一个廉价但真实拟合的模型写满。**
之后每次改进都原地原子覆盖。这样任何时刻被杀，盘上都有一份合法产物。
不要等到方法调好了再写第一次盘。

**A2. 兜底用的必须是拟合出来的模型。** 常数、全局均值、查表、复制输入——这些在评测
里等于没写。兜底可以简陋（岭回归、贪心、最近邻都行），但必须是真的从数据学出来的。

**A3. 落盘前硬校验输出契约：行数、槽位数、列名、dtype、取值域。**
校验不通过就不要写，宁可保留上一版合法产物。契约不符**不会报错、不会降分，会直接
判整个任务无效**，前面所有工作清零。

**A4. 多实例任务要在开跑前把预算显式切分给每个实例。**
先到先得的写法会让第一个实例吃光时间，剩下的实例输出零值，整题判 −1.0。

### B. 拿分

**B1. 不要写死训练步数。先跑 5–10 步实测 sec/step，用剩余墙钟反推步数。**

```
1. 试跑若干步，记录真实 sec/step（在实际执行的机器上测，不是凭经验猜）
2. 剩余墙钟 = 总预算 − 已用 − 推理/落盘/评测预留
3. n_steps = 剩余墙钟 / sec/step × 0.8
4. 训练中途定期检查是否偏离预算
5. 跑完打印「实际用量 / 总预算」
```

第 5 步是自检：**跑完只用了 40% 预算，这本身就是一个 bug**，不是节俭。

**B2. 动手建模之前，先把官方指标读成一个公式。** 具体要搞清楚：

- 哪些子指标真的进 aggregate，哪些是摆设
- 样本权重是什么的函数（如果是**标签**的函数，那朴素平均就是错的贝叶斯规则）
- 指标的解析上界在哪
- 指标只依赖排序，还是依赖绝对值

这件事的投入产出比在这批题里排第一。多道题的单次最大提升来自读懂指标而非改进模型。

**B3. 官方指标只看排序时，把训练目标也换到秩空间**（秩正态变换、pairwise 排序损失），
并且**显式放弃概率校准**——省下的算力投到有回报的方向。

**B4. 折外（OOF）选择加多视图集成是默认配置，不是加分项。** 融合权重在折外数据上用
NNLS 或单纯形约束定出来，不要手调，不要在测试分布上调。

### C. 别骗自己

**C1. 新机制默认关闭，必须由留出证据点亮；没点亮时输出要与基线逐字节一致。**
「逐字节一致」不是形式主义——它是区分「这个模块没用」和「这个模块悄悄让结果变差」的唯一办法。门槛要写明（例如折外指标须超基线 1e-3，或超过 max(0.002, 1 SD)）。

**C2. 把假设预注册成可证伪的开关，跑完报告它有没有被点亮。**
阴性结果也是结果。假设被证伪时走回退路径，并把这件事写进总结——不要含糊过去，也不要事后把假设改成已经发生的那个。

**C3. 划分必须按结构单元不相交**：scaffold、染色体、供体、蛋白聚类、时间段——取决于数据里真实的相关性来源。在有结构的数据上随机划分，验证分会好看，而且**是假的**。

**C4. 泄漏审计要打印成一个数。** `TEST_PAIRS_IN_TRAIN=0`、置换候选后 delta=0.0、
`assert_instance_owned(...)`。「我检查过了」不是审计。

## 二、避免做

下面每条都是实际发生过的失败模式，后面是它造成的后果。

**× 把训练步数、轮数、迭代次数写死。**
→ 猜大了超时判 −1；猜小了白白闲置一半墙钟。有六次跑完只用了 20%–48% 的预算，而验证指标在被截断的那一刻**仍在单调上升**（754.6/3600、1438.2/3600、445/3600、750/3000、1077/3450 秒）。有一次是成本模型把某个模块按每次循环重复计费，把上限永久算成了 0。

**× 假设执行环境和你估计的一样快。**
→ 实测出现过执行机比预期慢 **45 倍**的情况，3600 秒内一个模型都没拟合完。任何没有实测支撑的时间估计都不可信。

**× 把全部预算排给训练。**
→ 推理、落盘、后处理都要时间。有一次是评测端超时，最后靠把内部预算从 3600 压到 1200、候选数从 100 降到 16 才拿到分。

**× 用常数或查表当兜底路径。**
→ 兜底被触发时等于交白卷，而兜底恰恰是在最糟的情况下才会被触发。

**× 写完直接落盘，不校验形状。**
→ 出现过输出 5530 行但契约要求 13500 个稠密槽位，整个子任务判无效；也出现过写了个0 行的 CSV，valid=false。两次都是前面的建模工作全部作废。

**× 让新模块默认开启，或者关闭时走一条「差不多」的路径。**
→ 你会分不清没提升和变差。要么逐字节回退，要么这个消融不成立。

**× 为不进 aggregate 的子指标做优化。**
→ 有一道题的 aggregate 其实是单个子指标的纯函数，另一个子指标根本不进公式；为它花的算力全是沉没成本。动手前把公式读出来就能避免。

**× 在有结构的数据上随机划分。**
→ 有一道题换成结构不相交划分后才发现，**之前整条验证信号是失效的**，据此做的所有选择都不可信。

**× 跨实例复用特征时，把实例自己的标签也带进去。**
→ 堆叠、检索、kNN 增强都容易犯。要显式剔除自身列、做 self-excluded 检索、对近重复（相似度 > 0.9999）做截断。

**× 留着预算不用就交卷。**
→ 见第一条。跑完不检查余量，你永远不会知道自己亏了多少。

## 三、一句话版

**决策顺序**：先拿有效解 → 再诊断（预算吃满了吗、验证可信吗、指标读对了吗）→ 曲线
没到平台就微调、到了平台先回收工程浪费、都干净了才换方案 → 饱和的部分冻结，预算移
给最弱的。每次 attempt 只改一件事。

**规则**：开跑先落合法产物；实测反推预算，跑完检查余量；建模前把指标读成公式；新机
制默认关闭、由折外证据点亮、否则逐字节回退；划分按结构切，泄漏审计打印成数；落盘前
校验契约。
