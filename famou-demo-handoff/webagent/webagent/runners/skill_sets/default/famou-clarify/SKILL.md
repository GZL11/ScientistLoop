## 核心原则

澄清阶段包含两类问题，**都必须问，都用选择题格式**：

**A. 确认类**：你从数据或 query 中已形成某个理解，但这个理解可能是错的。把你的理解作为 default 选项提出来，让用户确认或纠正。不得因为"数据里已有"就跳过——读到的不等于理解正确。

**B. 疑惑类**：你确实不确定某个约束，query 和数据都没有给出答案。照常提问，default 填你的最佳猜测。

两类问题**混合在同一轮**中提出，形式完全相同（选择题 + default），区别只在于 default 是"你的现有理解"还是"你的猜测"。**必须至少发起一轮澄清**，不得跳过。

---

## 你的任务

1. 读取当前目录下的数据文件，结合用户传入的 query，形成对任务的完整理解
2. 按下方"任务类型判断"流程确定类型，读取对应领域参考文件，获取该场景下的约束清单
3. 对清单中每条约束，判断属于 A 类（我有理解，需确认）还是 B 类（我有疑惑，需询问），整理成选择题
4. 每轮最多提出 4 个问题，等待用户回复后继续下一轮，根据用户的选择需要动态判断需要问什么，是否追问
5. 所有约束覆盖完毕后，输出结构化结论

## 任务类型判断

**判断依据**：先读取当前目录下的数据文件，再结合 query，综合以下两类信号进行判断：
- **query 关键词**：问题描述、目标动词（预测/排程/配送/补货…）
- **数据文件特征**：列名、文件名、数据结构（如含 distance_matrix 往往是 routing；含 machine/job 往往是 scheduling）

按以下顺序逐步判断，**命中第一条即停止**：

```
1. 输出是预测值/误差评估，而非决策方案？
   → forecasting

2. 决策变量是连续值（角度、速度、坐标、参数），约束来自物理/几何方程？
   → continuous

3. 核心约束是以下哪种？
   ├─ 时间 × 资源分配（任务/飞机/船舶/手术 分配到时隙/泊位/机台）
   │   → scheduling
   ├─ 路径/回路构造（如何把节点串成行程）
   │   → routing
   ├─ 空间填充（把物体放入容器/在原料上切割）
   │   → packing
   ├─ 开关/匹配决策（开哪些设施、谁匹配谁），无时间维度
   │   → assignment
   ├─ 多期库存流转（何时订多少货，在供应网络中如何补货）
   │   → supply_chain
   └─ 流量守恒/功率平衡（弧上流量或时刻功率分配）
       → network_flow

4. query 和数据文件均无法确定类型
   → 将任务类型确认作为第一轮 clarify 的第一个问题提出（见下方示例），
     根据用户回答再读取对应参考文件，继续后续约束澄清
```

**类型不明时的问法示例**（放入第一轮 clarify 的第一题）：

```
{
  "label": "请问本次任务的核心目标是哪类优化问题？",
  "multi": false,
  "options": [
    "排程/调度（把任务分配到时间槽和资源上）",
    "路径规划（构造访问节点的最优路线）",
    "装箱/切割（把物品放入空间或在原料上切割）",
    "选址/分配（决定开哪些设施或谁匹配谁）",
    "库存/补货（多期内何时订多少货）",
    "能源/网络流（流量或功率的时序分配）",
    "需求预测（预测未来销量或需求）",
    "连续参数优化（物理/工程参数的数值求解）",
    "其他（请描述）"
  ],
  "default": "排程/调度（把任务分配到时间槽和资源上）"
}
```

**跨类型处理**：若 query 明确包含两个阶段（如"先预测需求，再做补货规划"），依次读取两个参考文件，分轮覆盖各自约束。

## 输出格式

### 每轮提问

每轮问题必须包裹在 `<clarify>` 标签内以 JSON 格式输出。**`default` 必须填入你的当前理解（A 类）或最佳猜测（B 类），不能为空或模糊**：

```
<clarify>
{
  "title": "确认几个关键信息",
  "questions": [
    {
      "label": "[A类示例] 换产费用：我理解同类产品互换 $500/次，A↔B 互换 $2000/次，涉及 C 类 $3500/次，是否正确？",
      "multi": false,
      "options": ["是，理解正确", "部分有误（请描述）", "其他（请描述）"],
      "default": "是，理解正确"
    },
    {
      "label": "[B类示例] 每天外包总量是否有上限？",
      "multi": false,
      "options": ["有上限，25吨/天", "有上限，其他数值（请描述）", "无上限", "其他（请描述）"],
      "default": "有上限，25吨/天"
    }
  ]
}
</clarify>
```

- `multi: false` 为单选，`multi: true` 为多选
- 最后一个选项**必须是'其他（请描述）'**
- 每轮最多 4 个问题，输出后等待用户回复

## 需要确认的约束维度

以下 8 类是通用维度，结合领域参考文件一起覆盖。**每类中只要与本任务相关，就必须确认**，不能因为"已知"而跳过。

### 1. 优化目标
需要确认：
- 优化目标是什么？单目标还是多目标？（把你读到的目标写出来让用户确认）
- 多目标时，优先级顺序是什么？
- 是否有惩罚项纳入目标函数？

### 2. 容量与资源限制
需要确认：
- 每个资源的容量上限及计量单位（把你从数据里读到的数值写出来）
- 是否有全局共享上限（全厂、全天）？

### 3. 操作规则
需要确认：
- 状态切换（换产、换泊位）时的规则：时间、费用、产能损耗
- 特殊类别之间的禁止组合或顺序约束

### 4. 成本结构
需要确认：
- 总成本的构成项（把你理解的各项费用列出来确认）
- 每项费用的计算公式、触发条件（按天？按件？按等级？）

### 5. 时间约束与窗口
需要确认：
- 截止日期的含义（当天完成 vs 当天之前开始）
- 工作制（每天可用工时、班次）
- 提前期数值及其含义

### 6. 弹性与替代规则
需要确认：
- 是否允许替代、外包、加班及其上限
- 需求满足是硬约束（100%）还是允许缺货并罚款

### 7. 结构与网络约束
需要确认：
- 各节点之间的调拨/采购关系
- 是否有覆盖性要求

### 8. 初始与边界状态
需要确认：
- 初始库存 / 初始状态的具体数值（把你从数据里读到的写出来）
- 计划期起始时间
- 车辆/人员是否需要返回起点

## 澄清轮次规则

- **必须至少发起一轮澄清**，不得跳过
- 每轮将本轮所有问题一次性输出，上限 4 个；A 类和 B 类问题混合排列
- 用户回复"对"/"继续"则采用 default；用户纠正则更新理解
- **追问要有深度**：A 类得到纠正后继续追问细节；B 类得到答案后若引出新的不确定性继续追问
- 所有约束覆盖后，加一个兜底问题：「以上是我对本任务约束的完整理解，还有我遗漏或理解错误的地方吗？」
