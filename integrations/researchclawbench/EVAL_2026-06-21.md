# ResearchClawBench 测评记录 · famou-scientist（2026-06-21）

> 本文记录把 famou-scientist 接入 ResearchClawBench（RCB）后的**首轮测评**：每个学科领域跑 1 个 case，
> 共 10 个，用 RCB 官方 judge（gpt-5.1）按隐藏论文 rubric 打分。接入方式见同目录 `README.md`，
> benchmark 背景见 `docs/benchmarks/BENCHMARKS_AI4S.md`（RCB 是我们「对外背书」的首选之一）。

## 1. 测评设置

| 项 | 值 |
|---|---|
| 被测 agent | famou-scientist（经 `integrations/researchclawbench/famou-rcb` 接入 RCB 的 `agents.json`） |
| 后端模型 | `claude-sonnet-4-6`（OpenCode 默认 provider） |
| Judge 模型 | `gpt-5.1`（RCB 官方 scorer，`structai` + 视觉打分） |
| 任务数 | 10（每领域 1 个，均为各领域 `_000`，Physics 用先期完成的 `_003`） |
| 重复 | **单次，无 repeat**（judge 有随机性，正式刷榜应 ≥3 次取均值±SEM） |
| 评分标尺 | 0–100，**50 = 与已发表论文同等水平**；对**隐藏的真实论文**逐条核对 |
| 评分模式 | 双模：Mode A 客观（定量结果 vs 论文）/ Mode B 主观（机制分析/推理）；图项用 VLM 看图 |

**RCB 怎么打分（关键）**：给 agent 一个**研究工作区**（只读 `data/` + `related_work/` + 任务说明），
要求它**全自主**完成研究并产出 `report/report.md` + 图；scorer 拿报告对**藏起来的原论文** rubric 逐条判，
50 分意味着「做到和原论文一样好」——这是很高的门槛。

## 4. 关键发现与解读

### 4.1 这是「地板分」，不是 famou 完整流水线的分（最重要）
RCB 的 `INSTRUCTIONS.md` 是一份强自包含的「全自主、产出 report/report.md」指令，**盖过了** famou
自己的 23 阶段方法论编排。结果是 famou **像一个通用自主 agent 在跑**（用了我们的 `arc_run_experiment`
真执行工具做数据分析/出图），但**没有走** `research-runs/` 流程、**没起** peer-review 子 agent、
**没过** quality-gate、**没触发**防编造门复盘。
→ **本批分实质 ≈「claude-sonnet-4-6 + 我们的真执行工具」**，famou 的方法论差异化没体现。要测「真 famou」，
需改接入让任务 prompt 走完整流程（见 §6 下一步）。

### 4.2 大量单项 0 分 = 没命中隐藏论文的特定产物
RCB 是**对隐藏真实论文逐条核对**。单项 0 不是「没做」，而是「没做到论文要求的那个具体结果/图」：
- **Neuroscience（1.0）**：5 项几乎全 0。rubric 要的是**六种条件下的 PR 曲线 + Lab1/Lab2、雌雄、RI/CSDS 的 SHAP 对比**等**非常具体**的诊断图；famou 做了 SimBA 式分类但没产出这些特定对照。
- **Energy（6.5）**：要 LHS 20 组 + 4 层 ANN 代理 + 用代理做参数辨识的具体三步链路与数值，famou 的实现与论文设定对不齐。
- **Life（7.8）**：8 项里只有「ML 优化出更强配方」这条拿到 48，其余特定图（24707 蛋白生信、UMAP 优化、R1-max 表征…）几乎全 0。
- 反例 **Physics（47.6）**：rubric 较定性（画出 Dirac 锥+复制带、偏振依赖图、点明 Volkov 机制），famou 都覆盖到了 → 接近论文水平。

**规律**：rubric 越定性/越靠「方向对+有图有结论」，famou 越接近论文水平；rubric 越要求**复现论文里某个特定
定量结果/特定对照图**，单次开放产出越难命中 → 这正是「自主开放产出」对「隐藏金标」的固有难点。

### 4.3 judge 有随机性
Physics 两次打分 45.4 / 47.6。正式刷榜须多次取均值±SEM。

### 4.4 评分标准是否清晰 × 低分归因(逐题)

**先回答「评分标准在任务描述里清不清晰」:对评分而言——刻意地不清晰。**
RCB 的 rubric 藏在隐藏论文的 `target_study/checklist.json` 里,**agent 从头到尾看不到**;
任务描述(`INSTRUCTIONS.md` 的 `{task_desc}`)只给「输入/输出/科学目标」三句话级别的**方向**,
**不给**「要画哪张特定对照图、要复现哪个定量数值」的细则。这是 benchmark 的**设计选择**(否则就退化成"按规格交付"而非"做研究"),
但它直接决定了:**低分的主因不是「agent 没按要求产出」,而是「rubric 对 agent 不可见 + 隐藏论文要的是特定产物」。**

一个硬事实:**10/10 都产出了 `report/report.md` + 图、都扣对了题**(标题见 §5)。
所以「没产出应有产物(按可见指令)」这一项**几乎不成立**——可见指令只要求"一份带图的报告",10 个全部满足。
真正拉低分的是下面这些**任务描述里没说、agent 无从得知**的东西。逐题归因:

| 领域 | 加权分 | item 分(按权重) | 低分主因 | 性质 |
|---|---:|---|---|---|
| **Physics** | 47.6 | 45(.5)/47(.3)/55(.2) | rubric 偏定性(Dirac 锥+复制带、Volkov 机制),与任务方向对齐 → 高;偏振 CSV 空只压住一条 | ✅ 方向=rubric,输入小缺口 |
| **Earth** | 28.4 | 47/40/28/**0**(.3) | 多数 partial;最重一项 0 = 某特定定量产物 + `glambie` 仅 4KB 难全量重建 | 🟡 不可见特定项 + 输入落差 |
| **Information** | 26.7 | 25/**0**(.3)/48(.4) | 理解/演示拿到 48;0 那条要**真训出文生图**——但**工作区只给 2 张测试图、零训练语料**,且训生成模型远超单次算力(详见 §4.5) | 🟠 缺训练数据 + 算力(非不产出) |
| **Math** | 21.6 | 25/35/**18**(.7) | 最重一项(.7)只 18 = 跟踪的**特定定量结果**(MOTA/IDF1 vs ByteTrack)没对齐 | 🟡 类型对、定量没命中/质量 |
| **Material** | 20.5 | 28/**3**(.3)/28(.5) | GNN 筛选两条拿 28/28;3 那条要**第一性原理(DFT)确认 50 个新交替磁体**——VASP 要 license、逐个材料数小时×50,单次沙箱不可达(详见 §4.5) | 🟠 专用工具链/许可 + 逐项重算 |
| **Astronomy** | 19.3 | 50(.2)/31/**0**(.5) | 框架本身拿 50;最重一项 0 = ULB 质量/耦合的**特定上限数值**没复现到论文 | 🟡 不可见特定数值 + 质量 |
| **Chemistry** | 18.8 | 20/28/**0**(.2) | KA-GNN 搭起来了,但**特定精度/AUC 数值** vs 论文没对齐;KAN 实现深度可能不足 | 🟡 定量没命中 + 质量 |
| **Life** | 7.8 | **0/48/0/0/2/5/15/0** | 8 条里只有「ML 优化更强配方」命中;其余(24707 蛋白生信、UMAP、R1-max 表征…)**任务里只字未提** | 🔴 rubric 高度论文特定且不可见 |
| **Energy** | 6.5 | **0(.3)/15/5** | 数据是 4KB **指针**(无实测曲线)+ rubric 要 LHS-20/4 层 ANN/辨识链路的**特定数值** | 🔴 输入缺失 + 不可见特定链路 |
| **Neuroscience** | 1.0 | **0/0/0/0/5** | rubric 要**六条件 PR + Lab1/2、雌雄、RI/CSDS 的 SHAP 对比**,而输入只有 SimBA 单工程样例 | 🔴 输入 vs rubric 客观落差,近乎不可命中 |

**归因桶(按对总分的影响排序):**
1. **rubric 不可见 + 论文特定(主因,几乎贯穿全部)**:任务只给方向,scorer 查的是隐藏论文的**特定数值/特定对照图**。大量"单项 0"属于此——**不是没做,是不知道要做那个特定产物**。
2. **输入落差**(Neuroscience/Energy/Earth/Physics):即便知道要什么也产不出——数据是空文件/指针/单工程样例(见 `CASE_INPUTS.md` 数据完整性小结)。
3. **沙箱/外部依赖天花板**(Material 要 DFT、Information 要真训生成模型):单次沙箱客观不可达,**非 agent 失误**——这类"做不出"其实分四种不同原因,且只有一种是任何 agent 都跨不过的真天花板,详见 §4.5。
4. **质量/深度不足**(次要):部分 partial 分(20–35)是"类型对了但没到论文深度",这才是真正可归为"产物质量不高"的部分——但占比小。
5. **单次 + judge 随机**(§4.3):放大尾部波动。

**结论**:得分低**主要不是 famou「没按要求产出对应产物」**(10/10 都交了报告+图、都扣对题),也**不主要是「产物质量不高」**(质量只解释了那些 20–35 的 partial 项)。
**主因是结构性的:评分标准对 agent 不可见,而隐藏论文要的是特定定量产物**,再叠加部分任务的**输入落差**与**沙箱上限**。
换句话说,这套分**在测「单次盲打能多接近某篇特定论文」**,而不是「agent 是否完成了一份合格的研究报告」——后者 10/10 都做到了。
→ 提分的真正抓手不是"写得更漂亮",而是 **(a) 让流程更会从 `related_work/` 反推 rubric 可能在意什么、(b) 补全输入数据、(c) 走完整 famou 流程(peer-review/quality-gate)逼出更接近论文的定量严谨度**(见 §6 下一步)。

### 4.5 「沙箱单次做不出」的四类原因，以及"任务需要外部软件却不提供"是不是悖论

§4.4 把 Information/Material 标成"🟠 沙箱/外部依赖天花板"。这句话太省,容易被误读成"GPU 不够"。
**先一个反证:沙箱是有算力的**——Chemistry 的 GNN 训了 ~38min、Material 的 GNN 筛选训了 ~35min 都正常跑完。
所以"做不出"不是"没 GPU",而是分下面四类**不同**原因:

| 原因 | 性质 | 例子 | 自主能跨过吗 |
|---|---|---|---|
| **缺训练数据**(工作区只给测试/演示数据) | 输入问题 | Information 只有 2 张测试图、零训练语料 | ❌ 没数据训不出 |
| **算力 × 时长预算**(单次 `max_runtime` 装不下) | 资源问题 | 训基础生成模型、50× DFT | 🟡 取决于预算 |
| **专用工具链 / 许可**(VASP 要 license 等) | 环境问题 | Material 的 DFT 确认 | 取决于是否开源 |
| **任务原本是数月 + 集群 + 实验室完成** | 结构错配 | 把"一篇论文的全部工作"压进一次自主会话 | ❌ 结构性 |

**关于你说的"需要外部软件却不提供 → 悖论":其实不是真悖论,要把"外部软件"再分两类:**

- **① 开源、可自己装/下的**(不是天花板,自主 agent 真能搞定):
  例如 DFT 里的 **Quantum ESPRESSO 是免费开源的**,`conda install` 即可、赝势文件可联网下、小规模能跑。
  这类"外部软件",自主 agent 的正解就是**该装的装、该下的下、该算的算**——前提是**沙箱给网络**(RCB 走环境变量代理 `ALL_PROXY`,通不通取决于起 RCB 那个 shell 的配置)。装好后卡点就**从"软件没有"退化成"算力/时长不够"**,不再是悖论。
- **② 要许可证 / 专用硬件 / 真实验仪器的**(这才是真天花板):
  例如 **VASP 要商业 license**、商业求解器、或干脆要真实验仪器(ARPES 束线、合成实验室)。
  这类**任何 agent 都自主搞不定**——但这**不是"agent 不行",而是"任务要的东西这个评测载体根本不提供"**,且它**对全场公平地压分**(Material 那条 DFT 全榜都难拿,最强 agent 总分也才 ~20)。

**所以"悖论感"来自 RCB 自己两个设计选择打架**:① rubric 取自**真实发表论文**(= 那篇论文真做过的事,含数月集群 DFT / 湿实验);② 让 agent 在**一次有时限的沙箱会话**里跑。对"重外部工具"的题,这两条天然拉开 → 该 criterion 对所有人接近不可达。这套分的标尺"50=论文水平"本就**默认了"离论文很远"**,测的是**距离**,不是"通过/不通过"。

**撞到 ② 这种墙时,正确做法 = 诚实降规模,绝不硬凑/编造:**
- 能装 QE 就**真跑一个小子集**(如 3–5 个候选做第一性原理,而非 50 个),其余用**更便宜的方法**(紧束缚 / 直接引用 Materials Project 已算好的值 / 模型预测)并**显式标注是近似**;
- 报告写清:"全量 50 个 DFT 确认超出本次算力,本文确认 N 个,其余用 X 方法佐证"。

这条诚实路径**仍会丢 rubric 分**(它不是"真 50× DFT"),但**是对的行为**——也正是 famou 的 **quality-gate / 数字核验门 / failure-mode-audit(防捷径 Mode 4)** 该发挥作用之处:**逼它如实说"只算了 N 个、其余是近似",不许假装跑了 50 个**。
**一个会"诚实承认天花板"的 agent,比一个"编出 50 个 DFT 结果"的 agent 更可信——哪怕前者分更低。**
→ 对 famou 的启示:这种题的差异化**不在"分更高",而在"诚实标注做不到的部分、不编造";**可再加一手——让流程**早期识别出"本题依赖不可提供的工具"→ 主动降规模并声明**,而不是闷头撞墙到超时。

## 6. 限定与下一步

**限定（避免高估）**：① 地板模式，非完整 famou 流程；② 单次无 repeat；③ 每领域仅 1 题（10/40），均为 `_000`。

**下一步（建议优先级）**：
1. **挖低分**：把 Neuroscience/Energy/Life 的 judge 逐条 reasoning 拉出来，确认是「没出对图」还是「结论错」，定位真实短板。
2. **跑「真 famou」模式**：改接入让它走完整 23 阶段（peer-review/quality-gate），验证方法论是否带来增益——这是验证我们差异化的关键实验。
3. **稳定性**：挑 2–3 个领域各跑 3 次，给均值±SEM。

**踩过的坑**：批量并发跑时，`while read ... < manifest` 循环里 `opencode run` 会**吃掉 manifest 的 stdin**，
导致后续任务不启动 → 子进程必须 `</dev/null` 隔离 stdin、manifest 用独立 FD 读（见 `/tmp/run_famou_batch2.sh`）。
